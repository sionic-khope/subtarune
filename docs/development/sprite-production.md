# 공통 이미지 제작 계약

진입점은 [sprite-production 스킬](../../.claude/skills/subtarune-sprite-production/SKILL.md)이다. 이 문서는 공급자와 무관한 결과 기준이며 API의 실제 지원은 별도로 확인한다.

## 생성 전에 남길 명세

요청 ID, 최신 원문과 교정, 사용 장면, 승인 참조 파일/기준 커밋, 변경할 동작·상태, 보존할 외형, 방향과 프레임 순서, 최종 셀/시트 크기, 프레임 시간·loop/one-shot, 공통 배율·피벗, 배경 처리, 출력 경로를 적는다. 모델·공급자·정확한 ID·참조 입력 방식·품질/해상도·생성 횟수/비용 상한은 별도 실행 설정이다. 미지원 필드를 조용히 생략한 결과는 같은 계약의 성공이 아니다.

참조 역할은 **정체성 / 도트 밀도 / 배치·몸체 배율 / 상태 변형**으로 명시한다. 예를 들어 파크 공격 변형은 기존 공격을 자세·배율 기준, 현재 헐렁임 대기를 상태 기준으로 삼는다. 프롬프트에 로컬 파일명만 쓰는 것은 그림을 실제 첨부한 것이 아니다.

## 외형과 도트

- 승인 그림의 실루엣·얼굴·옷·식별색을 유지한다. 작은 크기에서 읽히는 굵은 픽셀 군집과 계단식 윤곽, 단순한 명암을 맞춘다. 큰 생성 PNG를 축소했다고 원본의 도트 밀도가 자동으로 맞는 것은 아니다.
- 형섭/요플래의 기본 얼굴은 큰 U자 코와 안경, 코 아래 별도 입 없음이다. 경섭·쥰희·용준까지 입을 없애지 않는다. 변신·재판 컷인의 장면별 설정을 기본 이동 모습으로 역전파하지 않는다.
- 변경 부위 밖의 요소는 보존한다. 눈매 수정으로 뒷모습·옷·공격 전체를 교체하지 않는다. 사용자가 제공한 완성 도트를 그대로 쓰라고 한 경우는 생성이 아니라 기계적 정리다.
- 팔레트 개수·64px셀·2등신을 전체 캐릭터의 보편 규칙으로 고정하지 않는다. 큰 보스, 비인간형, TV 삽화는 현재 자산 계약과 실제 표시 크기가 우선이다.

## 동작별 시트

| 유형 | 구성 판단 | 실제 확인 |
|---|---|---|
| 일반 이동 | 현재 엔진 방향 순서/standing 프레임을 확인하고 방향별 연속 동작을 만든다 | down/up/left/right와 원본 행 순서를 명시적으로 변환; 좌우 거울복사로 안경·소지품 방향이 깨지지 않는지 확인 |
| 접지한 공격 | 준비→힘 모으기→타격→후속 동작→복귀, 필요한 길이만 사용 | 몸체/발 기준 유지, 무기와 손의 접점, 타격 포즈/발사/충돌 시간 일치 |
| 상태 변형 | 같은 동작의 의상·손상·자세 변형을 별도 자산으로 만든다 | 현재 상태가 idle뿐 아니라 공격/복귀에도 유지; 의도된 숙임은 크기 오류와 구분 |
| 점프·날림·낙하 | 몸체 모션과 월드 이동/중력/회전을 분리한다 | 의도된 공중 이동에 접지 규칙을 억지로 적용하지 않음; 충돌·착지·복귀 위치 연결 |
| 투사체·이펙트 | 큰 검기·먼지·탄환은 몸체와 별도 그림으로 만든다 | 투명 여백 때문에 몸체가 작아지거나 위협 판정이 커지지 않음 |
| TV·배경 포함 삽화 | 바뀔 전경과 고정 배경의 소유권을 분리한다 | 표정 변경마다 방·창·원근이 바뀌지 않음 |

몸체 생성은 한 동작의 다중 행 그리드를 기본으로 한다(예:4프레임2×2,6프레임2×3). 엔진이 한 줄 strip이나 여러 행동 atlas를 요구하면 통과한 프레임을 나중에 조립한다. 일반4방향 이동4×4는 하나의 이동군이므로 가능하다. 특정 패턴이6프레임을 썼다고 모든 동작을6장으로 늘리지 않는다.

접지한 여러 모션은 승인 기준의 **공통 샘플링 배율과 발 피벗**을 공유한다. 프레임마다 bbox를 꽉 채우는 독립 확대/축소는 몸 크기 진동을 만들므로 하지 않는다. 넓은 무기 때문에 몸체가 줄었다면 원본의 몸체 크기를 교정하거나 FX를 분리한다. 자연스러운 웅크림/천의 처짐은 실제 포즈 차이로 남긴다.

## 후처리 경계

배경 제거, 공통 crop/grid 분할, NEAREST 크기 조정, 방향 재배열, 피벗 정렬, atlas/GIF 조립은 기계적 처리다. 얼굴·의상·동작의 새 그림은 선택된 이미지 모델이 만든다. 기존의 사용자 승인 픽셀 보정·runtime sideWalk는 해당 계약의 예외이지 임의의 코드 그림 재디자인 허가가 아니다.

투명 출력이 검증됐으면 실제 alpha를 사용한다. 색키 경로는 단색 배경을 쓰고, 배경과 연결된 픽셀을 중심으로 제거하며 분홍 장식·피부·윤곽을 따로 확인한다. 체크무늬가 그림에 구워진 것은 투명이 아니다. 마젠타와 비슷한 색 전체를 지워 캐릭터의 분홍 해골/귀를 손상시키지 않는다. 팔레트 양자화·과도한 윤곽 정리는 자동 기본값으로 추가하지 않는다.

과거 처리 명령의 사용자 홈·임시 경로는 기록이지 현재 실행 위치가 아니다. 해당 source의 README/스크립트 입력을 읽고 현재 절대 경로로 해석한다. 기존 처리기를 재사용할 때도 그 파일의 가정(입력행/색키/출력크기)이 이번 raw와 맞아야 한다. 원본은 보존하고 처리 결과를 새 경로에 쓴다.

## 최종 결과 검수

1. PNG signature와 디코드, 실제 치수, 셀 분할 가능 여부, 방향/프레임 수, 비어 있는 프레임, alpha/배경 잔여를 확인한다. 파일 확장자·존재·용량만으로 통과하지 않는다.
2. **납품할 최종 파일**의 모든 프레임에서 잘린 손·발·귀·무기, 셀 경계 침범·paste clamp, 몸 크기·기준점 흔들림을 확인한다. 중간 처리 썸네일의 QC 수치를 최종 PNG 검사로 대신하지 않는다.
3. 승인 idle과 새 동작을 같은 배율로 나란히 보고 실제 재생한다. 키 포즈가 다른 행동으로 읽히고 복귀가 같은 캐릭터/상태로 이어져야 한다. 단순 통째 흔들기/늘이기로 공격을 대신하지 않는다.
4. 전용 소스 계약의 수치를 우선한다. 범용 경계/비율 수치는 점검 신호이지 모든 종의 합격 공식을 뜻하지 않는다. 비정상 drift를 감추려고 테스트 한계나 프레임별 배율을 늘리지 않는다.
5. 알려진 실패는 반려 원인과 다음 수정 대상을 기록한다. 수치 통과·생성자 자체 확인·독립 검수·사용자 승인을 구별하며, 기존 승인 파일 교체는 작업 범위에 포함됐을 때만 한다.

원본·최종 프롬프트·참조 역할·공급자/모델/설정(도구가 감추면 unknown)·최종 PNG·규격/시간·처리 재현 방법·비교/GIF·검수/한계를 `assets/source/<작업>/`에 보관한다. API 키나 원본 base64 전체를 로그/저장소에 남기지 않는다. **이미지 ready ≠ 게임 integrated**이며 게임 검수는 [회귀 검사](regression-checks.md)의 자산/표시 경로를 따른다.
