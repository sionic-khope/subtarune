# 공통 이미지 제작 계약

진입점은 [sprite-production 스킬](../../.claude/skills/subtarune-sprite-production/SKILL.md)이다. 이 문서는 공급자와 무관한 결과 기준이며 API의 실제 지원은 별도로 확인한다.

## 생성 전에 남길 명세

요청 ID, 최신 원문과 교정, 사용 장면, 승인 참조 파일/기준 커밋, 변경할 동작·상태, 보존할 외형, 방향과 프레임 순서, 최종 셀/시트 크기, 프레임 시간·loop/one-shot, 공통 배율·피벗, 배경 처리, 출력 경로를 적는다. 모델·공급자·정확한 ID·참조 입력 방식·품질/해상도·생성 횟수/비용 상한은 별도 실행 설정이다. 미지원 필드를 조용히 생략한 결과는 같은 계약의 성공이 아니다.

참조 역할은 **정체성 / 도트 밀도 / 배치·몸체 배율 / 상태 변형**으로 명시한다. 예를 들어 파크 공격 변형은 기존 공격을 자세·배율 기준, 현재 헐렁임 대기를 상태 기준으로 삼는다. 프롬프트에 로컬 파일명만 쓰는 것은 그림을 실제 첨부한 것이 아니다.

## 요청에 따른 제작 범위

명시한 방향·행동·제외 사항이 기본 세트보다 우선한다. 일반 이동 요청에 방향 지정이 없으면 4방향 걷기를 기본으로 삼되, 프레임 수와 셀은 해당 캐릭터/엔진 계약을 따른다. “좌우만, 전투는 안 만듦”은 좌우 이동만 만든다. 이후 “위아래도”는 승인된 좌우 파일의 바이트와 규격을 보존하고 위아래를 추가한다. 새 통합 시트는 별도 경로에 조립하고 기존 좌우 셀과 동일한지 비교한다. 이미 승인된 자세까지 재생성해야 한다면 이유와 교체 범위를 먼저 알린다.

“모든 모션을 다룰 수 있는 스킬”은 아래 분기를 갖추라는 뜻이지 매번 전부 유료 생성하라는 뜻이 아니다. 대기/이동/전투/표정/타일 중 요청한 납품물을 구분하고, 세부 동작은 최신 설명과 승인된 게임 동작으로 결정한다. “전투 모션”만 주어지면 기존 전투 계약에서 필요한 대기·공격을 확인한다. 무기·능력이 정해져 있지 않고 선택에 따라 캐릭터나 게임성이 달라지면 한 가지를 질문하거나 범위를 밝힌 후보안을 제시한다. 새 무기·능력을 생성 프롬프트에서 임의로 확정하지 않는다.

## 외형과 도트

- 승인 그림의 실루엣·얼굴·옷·식별색을 유지한다. 작은 크기에서 읽히는 굵은 픽셀 군집과 계단식 윤곽, 단순한 명암을 맞춘다. 큰 생성 PNG를 축소했다고 원본의 도트 밀도가 자동으로 맞는 것은 아니다.
- 형섭/요플래의 기본 얼굴은 큰 U자 코와 안경, 코 아래 별도 입 없음이다. 경섭·쥰희·용준까지 입을 없애지 않는다. 변신·재판 컷인의 장면별 설정을 기본 이동 모습으로 역전파하지 않는다.
- 변경 부위 밖의 요소는 보존한다. 눈매 수정으로 뒷모습·옷·공격 전체를 교체하지 않는다. 사용자가 제공한 완성 도트를 그대로 쓰라고 한 경우는 생성이 아니라 기계적 정리다.
- 팔레트 개수·64px셀·2등신을 전체 캐릭터의 보편 규칙으로 고정하지 않는다. 큰 보스, 비인간형, TV 삽화는 현재 자산 계약과 실제 표시 크기가 우선이다.

## 동작별 시트

| 유형 | 구성 판단 | 실제 확인 |
|---|---|---|
| 대기 | 호흡·춤 등 요청한 작은 반복 동작과 정지 대표 프레임을 정한다 | 발 접지와 실루엣 유지; 대기가 공격이나 전진처럼 읽히지 않음 |
| 걷기·달리기 | 방향별 접지→통과→반대발 접지→통과를 설계한다. 달리기는 요청된 보폭·공중 구간에 맞춘다 | down/up/left/right와 원본 행 순서를 명시적으로 변환; 뒷모습에 정면 얼굴이 남지 않고 좌우 거울복사로 의상·소지품이 깨지지 않음 |
| 접지한 공격 | 준비→힘 모으기→타격→후속 동작→복귀, 필요한 길이만 사용 | 몸체/발 기준 유지, 무기와 손의 접점, 타격 포즈/발사/충돌 시간 일치 |
| 시전·스킬 | 준비→집중/hold→발동→회복을 요청된 기술에 맞춘다 | 몸체와 광원·투사체를 분리하고 실제 발동 시점을 표시; FX가 자세를 가리지 않음 |
| 피격·쓰러짐/사망 | 충격→반동→회복 또는 최종 정지 자세를 구분한다 | 피격 loop와 사망 자동 복귀를 혼동하지 않음; 마지막 자세와 완료 상태 명시 |
| 감정·기타 행동 | 인사·웃음·앉기 등 요청된 의미의 핵심 자세와 시작/종료를 정한다 | 걷기 포즈 재사용으로 다른 행동이라 주장하지 않음; 소품 접촉과 복귀 연결 |
| 대화창 초상화 | 요청된 표정/발화만 별도 얼굴 규격으로 만든다 | 신체 이동 시트를 덤으로 만들지 않음; 프레임 사이 얼굴 크기와 시선 유지 |
| 상태 변형 | 같은 동작의 의상·손상·자세 변형을 별도 자산으로 만든다 | 현재 상태가 idle뿐 아니라 공격/복귀에도 유지; 의도된 숙임은 크기 오류와 구분 |
| 점프·날림·낙하 | 몸체 모션과 월드 이동/중력/회전을 분리한다 | 의도된 공중 이동에 접지 규칙을 억지로 적용하지 않음; 충돌·착지·복귀 위치 연결 |
| 투사체·이펙트 | 큰 검기·먼지·탄환은 몸체와 별도 그림으로 만든다 | 투명 여백 때문에 몸체가 작아지거나 위협 판정이 커지지 않음 |
| TV·배경 포함 삽화 | 바뀔 전경과 고정 배경의 소유권을 분리한다 | 표정 변경마다 방·창·원근이 바뀌지 않음 |

몸체 생성은 한 동작의 다중 행 그리드를 기본으로 한다(예:4프레임2×2,6프레임2×3). 엔진이 한 줄 strip이나 여러 행동 atlas를 요구하면 통과한 프레임을 나중에 조립한다. 일반4방향 이동4×4는 하나의 이동군이므로 가능하다. 특정 패턴이6프레임을 썼다고 모든 동작을6장으로 늘리지 않는다.

접지한 여러 모션은 승인 기준의 **공통 샘플링 배율과 발 피벗**을 공유한다. 프레임마다 bbox를 꽉 채우는 독립 확대/축소는 몸 크기 진동을 만들므로 하지 않는다. 넓은 무기 때문에 몸체가 줄었다면 원본의 몸체 크기를 교정하거나 FX를 분리한다. 자연스러운 웅크림/천의 처짐은 실제 포즈 차이로 남긴다.

## 그림의 프레임과 코드의 전환

생성 프롬프트에는 각 프레임에서 달라질 자세와 이어질 동작을 적는다. 네 칸에 같은 그림을 복제한 결과는4프레임 동작이 아니다. 다만 중립→발A→중립→발B처럼 의도된 중립 반복/hold는 허용하며, 손·발·몸의 실제 포즈 차이와 마지막→첫 프레임 연결을 미리보기로 확인한다.

시트의 셀 수와 서로 다른 포즈 수를 각각 기록한다. 근소한 얼굴/윤곽 흔들림은 새 동작 단계가 아니며, 2자세 반복을 4개의 독립된 걷기 포즈라고 납품하지 않는다. 각 단계에 판독 가능한 손·발·무게중심 변화를 지정하고, 준비/타격/복귀의 duration을 의도에 맞게 배분한다. 모든 셀을 같은 속도로 넘기는 것은 실제 재생 확인을 거쳐 선택하는 설정이지 자동 정답이 아니다.

납품 계약은 행/열·인덱스 기준·방향별 셀 대응·재생 순서·각 duration·loop/one-shot·피벗을 명시한다. 생성 이미지가 이 시간이나 전환 로직을 실행하는 것은 아니다. 정지·방향 전환·다른 행동/상태로 교체, 일회성 완료/중단 후 돌아갈 상태는 [코딩 전달 계약](../../.claude/skills/subtarune-sprite-handoff/SKILL.md)에서 별도로 연결하고 검증한다.

## 타일·맵 소품

타일 요청은 캐릭터의 발 피벗/crop 규칙 대신 **격자·접속·레이어** 계약을 사용한다. 기존 맵이 있으면 타일 단위, 시점, 팔레트, 충돌 표현, atlas 등록 방식을 먼저 확인한다. “나중에 쓸 타일”처럼 엔진 규격이 미정이면 선택한 임시 타일 크기와 시점을 명시하고 자산만 납품한다. 새 맵·전투·충돌 코드를 요청 없이 통합하지 않는다.

| 범주 | 생성·납품 기준 | 검수 장면 |
|---|---|---|
| 반복 바닥 | 셀 전체를 채우는 full-bleed 바닥과 필요한 변주; 투명 여백/바닥 그림자는 넣지 않는다 | 같은 타일 3×3 반복과 변주 혼합에서 이음선·밝기 격자·두드러진 반복 확인 |
| 경계·모서리 | 요청된 바닥 쌍의 직선 경계, 바깥/안쪽 모서리, 필요한 끝부분을 접속 규칙과 함께 만든다 | 닫힌 둘레와 오목한 구간을 실제 조립; 빠진 방향·틈·두께 불일치 확인 |
| 나무·바위·장식 | 투명 소품과 바닥을 분리; 여러 셀을 차지하면 점유 크기·기준 위치·앞뒤 레이어를 명시한다 | 인접 타일 위에 배치하여 밑동 접지, 외곽 alpha, 겹침/가림 순서 확인 |

타일 ID→atlas 셀/크기→접속 가능한 이웃→바닥/장식/전경 레이어→통과/장애물/부분 충돌의 의도를 기록한다. 충돌을 아직 엔진에서 구현하지 않았으면 이 메타데이터는 설계 의도이며 검증 완료된 판정이 아니다. 그림의 가지/그림자 전체를 자동 충돌로 취급하지 않는다. 엔진이 autotile을 요구하면 그 엔진의 비트마스크·셀 순서에 맞추고, 미확정이면 보편적인 autotile 완성품이라고 주장하지 않는다.

“짜장숲” 같은 새 테마는 이름에서 택한 색·재질 해석을 먼저 밝히고, 바닥/경계/소품을 같은 도트 밀도로 맞춘다. 장식이 실제 보행 공간을 삼키지 않도록 반복 배치 예시를 함께 제공한다. 캐릭터 시트의 빈 배경 제거 절차를 full-bleed 바닥에 적용하지 않는다.

## 후처리 경계

배경 제거, 공통 crop/grid 분할, NEAREST 크기 조정, 방향 재배열, 피벗 정렬, atlas/GIF 조립은 기계적 처리다. 얼굴·의상·동작의 새 그림은 선택된 이미지 모델이 만든다. 기존의 사용자 승인 픽셀 보정·runtime sideWalk는 해당 계약의 예외이지 임의의 코드 그림 재디자인 허가가 아니다.

투명 출력이 검증됐으면 실제 alpha를 사용한다. 색키 경로는 단색 배경을 쓰고, 배경과 연결된 픽셀을 중심으로 제거하며 분홍 장식·피부·윤곽을 따로 확인한다. 체크무늬가 그림에 구워진 것은 투명이 아니다. 마젠타와 비슷한 색 전체를 지워 캐릭터의 분홍 해골/귀를 손상시키지 않는다. 팔레트 양자화·과도한 윤곽 정리는 자동 기본값으로 추가하지 않는다.

과거 처리 명령의 사용자 홈·임시 경로는 기록이지 현재 실행 위치가 아니다. 해당 source의 README/스크립트 입력을 읽고 현재 절대 경로로 해석한다. 기존 처리기를 재사용할 때도 그 파일의 가정(입력행/색키/출력크기)이 이번 raw와 맞아야 한다. 원본은 보존하고 처리 결과를 새 경로에 쓴다.

## 최종 결과 검수

1. PNG signature와 디코드, 실제 치수, 셀 분할 가능 여부, 방향/프레임 수, 비어 있는 프레임, alpha/배경 잔여를 확인한다. 파일 확장자·존재·용량만으로 통과하지 않는다.
2. **납품할 최종 파일**의 모든 프레임에서 잘린 손·발·귀·무기, 셀 경계 침범·paste clamp, 몸 크기·기준점 흔들림을 확인한다. 중간 처리 썸네일의 QC 수치를 최종 PNG 검사로 대신하지 않는다.
3. 캐릭터는 승인 idle과 새 동작을 같은 배율로 나란히 보고 실제 재생한다. 키 포즈가 다른 행동으로 읽히고 복귀가 같은 캐릭터/상태로 이어져야 한다. 단순 통째 흔들기/늘이기로 공격을 대신하지 않는다. 타일은 위 타일 검수 장면을 최종 atlas로 조립해 확인한다.
4. 전용 소스 계약의 수치를 우선한다. 범용 경계/비율 수치는 점검 신호이지 모든 종의 합격 공식을 뜻하지 않는다. 비정상 drift를 감추려고 테스트 한계나 프레임별 배율을 늘리지 않는다.
5. 알려진 실패는 반려 원인과 다음 수정 대상을 기록한다. 수치 통과·생성자 자체 확인·독립 검수·사용자 승인을 구별하며, 기존 승인 파일 교체는 작업 범위에 포함됐을 때만 한다.

원본·최종 프롬프트·참조 역할·공급자/모델/설정(도구가 감추면 unknown)·최종 PNG·규격/시간·처리 재현 방법·비교/GIF·검수/한계를 `assets/source/<작업>/`에 보관한다. API 키나 원본 base64 전체를 로그/저장소에 남기지 않는다. **이미지 ready ≠ 게임 integrated**이며 게임 검수는 [회귀 검사](regression-checks.md)의 자산/표시 경로를 따른다.
