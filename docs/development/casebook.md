## 독립 실행 과제

다음 중 변경 분야에 해당하는 요청 원문, 저장소 경로, 해당 스킬 경로만 평가자에게 준다. 읽기 전용으로 요구 해석, 읽은 파일, 구체 작업안과 판정 방법을 제출하게 한다. 이 문서의 아래 평가 포인트는 먼저 전달하지 않는다.

1. “만카츠키 다음 보스는 악기 쓰는 편집자야. 피격 데미지는 그대로 두고 더 어렵게. 리듬 기믹도 가능하면 아이디어만 줘.”
2. “영클 다음 방을 좀 더 어둡게 하고 상자 퍼즐 하나 넣어. 해결하고 돌아와도 풀려 있어야 해.”
3. “관중은 원래 앉아 있고 화면이 축소되면서 드러나게. 노란 스포트라이트는 부드럽게, 감사합니다에서 브금 다시 큐.”
4. “아이템이 많아지니까 메뉴 아래가 잘려. C 연타로 아이템이 두 번 써지는 것도 고쳐.”
5. “그림은 Codex가 만들 거고 Claude가 코딩할 거야. 큰 보스 인사 모션이 필요한데 기존 인형탈 외형은 유지해.”
6. “복구한 작업 이어서 요구사항대로 끝내고 바로 메인 반영해.”
7. “Fable이 이어서 코딩할 거야. 재판은 파크가 원래 채팅으로 말하고 회피할 때 죄명만 남겨. 답은 하나씩 다 읽고 나서 제한시간이 시작돼야 해. 음악은 계속 이어줘.”
8. “레이저가 그냥 왼쪽 오른쪽으로 도네. 내가 움직이는 하트를 따라오게 해줘. 소리는 지금 원음 순서 유지하고.”
9. “탈이 흘러내린 상태인데 때릴 때 갑자기 멀쩡해져. 공격 뒤에도 그 상태로 돌아와야 해. 박치기 때 둘이 날아갔다 빠맨 달려오는 건 유지해.”
10. “이전에는 재판 한 번이었는데 이제 두 번 해줘. 검수 로그는 이미지 오류라는데 원본은 열려. 최신 요구와 남은 작업부터 확인하고 이어가.”

## 평가 포인트

1은 피해/HP를 올리지 않는 패턴 아이디어와 제안 상태, 모드 계약을 찾는지 본다. 2는 영클 자산/생성기/리셋·저장·재입장/상자 접근을 본다. 3은 관중 소환과 사각형 고정 규칙을 피하고 카메라·색·큐를 분리하는지 본다. 4는 실제 입력·긴 목록·소비 중복·취소를 다루는지 본다. 5는 기존 자산 탐색·원본·프레임/피벗·담당 분리·runtime 확인을 요구하는지 본다. 6은 실제 worktree·최신 요구·증거를 복구하고 기존 권한으로 완료하는지 본다.

실행 결과는 날짜·평가 모델(알 수 있을 때만)·원본 SHA/미커밋 범위·읽은 파일·답변·통과/수정 사유로 작업 증거에 남긴다. 이 과제는 판단 절차 검증이며 실제 전투/화면 QA나 모델 능력 동일성의 증거는 아니다.

7은 기존 화자/초상화/음성 경로와 완독 기준, 제한시간·입력 개방, 같은 BGM 객체/시계의 증거를 찾는지 본다. 8은 현재 목표 갱신과 최단 각도/각속도, 공유 판정 및 실제 음성 시계를 다루는지 본다. 9는 단계×행동 대응과 복귀, 별도 몸체 상태와 동반비행 보존을 확인하는지 본다. 10은 새 요구를 과거 버그로 소급하지 않고 최신 원장과 원본 디코드/검사 schema/원시 로그를 대조하는지 본다. 이 추가 과제는 실행 전이며 작성자의 자체 PASS를 붙이지 않는다.
