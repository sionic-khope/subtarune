# 맵·퍼즐 구성 판단

생성/배치 문법은 [map 스킬](../../.claude/skills/map/SKILL.md), 이 문서는 새 맵에서 무엇을 결정하고 어떻게 관찰할지 다룬다.

1. **구간 역할:** 연결 통로/학습/변형/휴식/대치/공연 중 이번 방의 목적을 적는다. 연결 통로에 의미 없는 긴 걷기를 붙이거나 휴식 공간을 적으로 가득 채우지 않는다.
2. **공간 콘티:** 입구 → 첫 인지 → 행동/위협 → 결과 → 출구 순서와 플레이 시간을 정한다. 선택 조우는 본길과 구별되는 주머니, 회복은 위험 뒤 읽히는 위치, 막힌 길은 열 방법이 보이는 위치에 둔다. 방 수·폭·길이는 과거 맵의 숫자를 복사하기보다 현재 이동 속도/카메라/기믹 시간을 기준으로 정한다.
3. **지역 연속성:** 인접 맵의 실제 바닥·벽·원경·음악을 확인하고 파일을 선택한다. 영클의 어둡고 차가운 방은 영클 철판 위에서 조정한다. “보라/공허”라는 말만으로 옛 허공 지역 세트를 가져오지 않는다.
4. **배치:** `tools/maps/<id>.py`에서 생성하고 JSON과 index/양방향 spawn/QA 상태를 맞춘다. 걷는 지형·장식 그림·충돌·조사 영역·카메라 앵커를 서로 구별한다. 공연장의 관객처럼 원래 거기 있던 것은 맵에 존재하고, 카메라로 보여 주는 순간과 생성 시점을 분리한다.
5. **걷기 검사:** 실제 입구에서 출구까지, 귀환·재입장까지 이동한다. 소품 조사는 접근 가능한 좌/중/우와 끝까지 붙은 위치에서 C를 눌러 본다. 테스트 편의 좌표 한 곳의 성공으로 통과시키지 않는다.

## 새 퍼즐의 최소 계약

각 퍼즐에 시작 상태, 가능한 입력, 보이는 피드백, 성공 조건, 실패/교착 복구, 완료 저장, 재입장을 적는다. 처음 보는 규칙을 하나 학습시킨 뒤 배열/제약을 바꿔 응용한다. 같은 상자를 늘리거나 길만 길게 만드는 것으로 다양성을 대신하지 않는다.

영클 `src/world/factory-puzzles.js`는 상자 격자 이동·moveArea·충돌·회로판·리셋·완료 스크립트의 재사용 사례다. `src/data/cutscenes/factory_puzzles.js`와 `tools/maps/youngcle2.py`, `youngcle3.py`를 함께 본다. 기존 동작이면 데이터로 변형하고, 새 입력/상태가 필요할 때만 엔티티 계약을 늘린다.

상자를 잘못 밀어도 리셋에 접근 가능한지, 해결 중 대사가 열려도 완료가 유실/중복되지 않는지, 해결 후 돌아오면 통로와 flag가 일치하는지 본다. 선택 퍼즐을 QA 편의를 위해 강제 완료시키지 않는다.

## 읽히는 공간

- 열린 통로는 방향키 진입, 닫힌 문/조사 대상은 C라는 현재 입력 계약을 실제 그림과 대조한다. 단순히 PNG가 있다는 이유로 C를 요구하지 않는다.
- 장식은 용도와 지역을 설명하고 행동할 여백을 남긴다. 모든 빈 면을 소품으로 채우지 않으며, 무대/공장 같은 용도가 사라질 만큼 필요한 구조물을 지우지도 않는다. 비상호작용 장식에 새 대사를 자동 생성하지 않는다.
- 발밑은 연속된 통행 면, 벽/문은 읽히는 경계, 경고는 실제 위험 영역에 둔다. 캐릭터 그림 전체를 충돌로 쓰거나 넓은 그림의 밑동만 조사 영역으로 고정해 접근 끝에서 C가 빠지는 오류를 구분한다.
- 스폰/착지/정렬은 플레이어 몸체와 solid 소품까지 포함해 안전해야 한다. `freeSpot` 보정으로 원래 배치가 크게 밀린다면 콘티를 먼저 고친다. 구출 보정은 부자연스러운 경로의 대체물이 아니다.
- 대화창/패널을 뺀 화면 예산은 `src/core/layout.js`에서 읽는다. 맵 폭이 넓어도 현재 카메라에서 출구·주체·관객이 보이지 않으면 목적을 달성한 것이 아니다.

수치 감사는 `tests/unit/maps-layout.test.mjs`, `maps-connect.test.mjs`, `youngcle1-map.test.mjs`, `editor-union-map.test.mjs`가 사례다. 최종적으로 간격·반복 밀도·가림·빈 걷기 시간을 실제 입력과 화면으로 판단한다.
