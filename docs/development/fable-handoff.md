# Fable 등 다른 코딩 담당자의 진입점

이 파일은 다른 모델에서도 읽을 수 있는 작업 안내다. 특정 Fable 제품의 자동 스킬 설치나 도구 지원을 가정하지 않는다. 기본 진입은 저장소 [AGENTS.md](../../AGENTS.md) → [CLAUDE.md](../../CLAUDE.md) → [공통 판단](quality-contract.md)과 STATE의 해당 최신 항목이다. `/skill` 실행기가 없어도 링크된 SKILL.md를 직접 읽으면 된다.

## 역할 분리

코딩 담당은 요구 해석·엔진 연결·상태/입력·테스트·승인된 메인 반영을 맡는다. 이미지 담당은 [공통 이미지 스킬](../../.claude/skills/subtarune-sprite-production/SKILL.md)에 따라 선택된 도구/API로 그림을 만들고 검수한다. 한 에이전트에 실제 API 실행 도구가 있으면 양쪽 역할을 수행할 수 있지만 자산 ready와 게임 integrated는 구분한다. 모델을 바꿔도 현재 승인 자산과 작업 계약은 바뀌지 않는다.

## 첫 작업에서 확인할 것

1. 이번 추가 피드백을 기존 미완료 요청에 합치고 바뀐 축만 교정한다. ‘빛이 해 같다’는 색/경계/연속성 문제인지 보고 별도 태양을 추가하지 않는다. 과거 초안 수치 대신 현재 장면별 계약을 읽는다.
2. 장면/전투 표현은 [연출](staging.md)·[전투 판단](combat-design.md), 새 아이디어는 [기획 스킬](../../.claude/skills/subtarune-design/SKILL.md), 메뉴는 [UI 스킬](../../.claude/skills/subtarune-ui/SKILL.md)로 들어간다. 예시를 통째 복제하지 말고 플레이어 입력·원인·결과·상태 소유권을 현재 요구에 대응시킨다.
3. 변경 전에 [회귀 검사표](regression-checks.md)로 영향을 받는 기존 소비자를 정한다. 공통 메뉴/입력/전투 파일을 고치면 새 보스만 보는 것으로 끝내지 않는다.
4. 모델/도구 한계는 실제로 확인한다. 셸이 있다고 내장 이미지 도구가 생기지 않고, vision 입력이 있다고 그림을 생성하지 않는다. OG의 참조 지원 미확인은 이미지 스킬의 provider 문서에 남긴다.
5. 인계에는 요청별 완료/남음, 기준 SHA/변경 범위, 사용한 자산 계약, 실제 실행/미확인 범위, 다음 행동을 남긴다. 사용자 만족이나 다른 모델의 동등 성능을 테스트 수로 보장하지 않는다.

## 다른 담당자에게 보낼 시작 문장

> 이 저장소의 AGENTS.md와 docs/development/fable-handoff.md를 읽고 현재 요청을 진행해. 승인된 캐릭터/도트/연출을 유지하고, 새 이미지는 subtarune-sprite-production과 sprite-handoff의 선택된 공급자 경로로 제작해. 변경 영향별 회귀 검사와 실제 화면/입력 확인을 마치고, 이미 승인된 메인 반영 범위대로 전달해. 없는 도구·미확인 API·안 한 검사를 실행했다고 보고하지 마.

이 문장은 신규 API 과금·외부 업로드·게임 내용 변경을 일괄 승인하지 않는다. 구체 작업과 권한은 사용자의 현재 요청이 정한다.
