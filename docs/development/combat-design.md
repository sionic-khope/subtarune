# 전투·패턴·난이도 판단

새 적/패턴/전투 기믹을 설계할 때 읽는다. 구현 계약은 [적 추가 가이드](../battle/adding-enemies.md), 현재 수치는 `src/data/enemies.js`, 파티·강화 복원은 `src/core/story.js`가 원본이다.

## 먼저 플레이어의 판단을 설계한다

1. 적의 신체·소지품·성격에서 공격 행동을 고른다. 공격마다 **행동 → 화면 실루엣 → 예고 → 플레이어 대응 → 끝난 뒤 여유**를 적는다.
2. 이전 적과 회피법·경로·시간차를 대조한다. 탄 색·속도·개수만 바꾼 패턴은 새로운 놀이가 아니다. 예를 들어 만카츠키의 음식 포물선/오토바이 돌진/분신 교차 공격은 소재뿐 아니라 공간을 읽는 방식이 다르다.
3. 첫 노출은 대응법 하나를 읽을 수 있게 하고, 다음 변형에서 위치·방향·시간차를 바꾼다. 이미 배운 대응을 조합하는 후반 패턴은 허용하되 동시에 수행할 수 있는 탈출 경로가 있어야 한다.
4. 화면을 더 채우기 전에 플레이어가 실제로 어디로 움직이고 언제 결정을 바꾸는지 확인한다. 한 구석 정지로 무한 회피되거나 어떤 선택도 결과를 바꾸지 못하면 설계 목적을 다시 본다.

## 공정성과 난도는 함께 검사한다

경고는 피해를 주지 않는다. 실제 타격 도형과 보이는 위협은 같은 위치·크기·방향을 사용한다. 선/다각형/장판은 그리기와 충돌이 공유하는 기하를 확인한다. 그림의 투명 여백 전체를 큰 판정으로 취급하지 않는다.

빠른 위협의 `warn >= 0.3초`는 기존 최소 계약이지 공정함의 충분조건이 아니다. 유효 탈출 거리를 d, 실제 소울 속도를 v라 할 때 d/v가 주어진 시간 안에 들어오는지 보고, 소울 크기와 다른 위협이 막는 공간도 포함한다. 프레임이 건너뛰어도 예고·발사·종료가 중복되거나 사라지지 않는지 확인한다.

다음 세 축을 구분해서 조정한다.

| 요청 축 | 조정 대상 | 비교 조건 |
| --- | --- | --- |
| 회피가 더 어렵게 | 교차·시간차·안전 통로 이동·연속 방향 전환 | 소울 속도·무적시간·HP·피해·턴 길이를 동일하게 놓고 우선 비교 |
| 맞으면 더 아프게 | 해당 적/구간의 damage | 실제 도달 파티 HP·강화·회복 자원을 기준으로 몇 번 버티는지 |
| 전투 길이/압박 조절 | HP·공방 수·지원 행동·회복 배치 | 필수 이동/대사/연출 시간과 전투 시간을 따로 측정 |

“패턴을 어렵게”를 HP·피해량 증가로 대체하지 않는다. 반대로 사용자가 특정 후반 적 피해량 +5를 요청하면 그 범위만 올리고 기존 일반몹 전체를 재균형화하지 않는다. 과거 예시의 피해10~14/공격1/턴4~5초는 현재 전체 게임의 고정 수치가 아니다.

난도 검토에는 해당 구간의 정상 진행 파티/공격/영구강화/소모품을 사용한다. 기본 공격 예상 라운드는 적 HP ÷ (공격력 × 행동 가능한 파티원 수)를 대략적인 출발점으로 삼고, 쓰러짐·회복·특수 공격·대사 시간을 포함한 실제 플레이와 대조한다. 초기값만으로 후반 보스를 평가하지 않는다.

정지 중앙·네 구석·가장자리·단순 좌우 왕복·테두리 순환을 검사하고, 예고를 따라 피하는 경로도 검사한다. 앞의 방법이 통한다고 무조건 제거하는 것이 아니라, 패턴이 가르치려는 대응을 완전히 무력화하는 영구 안전지대인지 구분한다. 자동 회피 성공은 사람에게 적정 난도라는 증거가 아니다.

## 확장 위치를 먼저 고른다

| 필요한 변화 | 우선 소유 위치 | 유지할 계약 |
| --- | --- | --- |
| 적 고유 탄·예고·이동 | 전용 패턴 모듈 + 적 데이터 | `duration/update`, emit/box/soul/rnd/sfx 계약 |
| 공격 입력을 리듬·조준·타이밍으로 교체 | `src/battle/modes.js`의 attack 등록 | update 완료 신호, 공통 명중·승패 |
| 적 턴을 다른 놀이로 교체 | 같은 레지스트리의 enemy 등록 | 공통 파티 피해·라운드 종료 |
| 공방 사이 지원 행동·충전 | `src/battle/support/baron-cannon.js` 사례 | 행동 소비·해금·리트라이 초기화 |
| 무대 표현만 변경 | `src/battle/backgrounds.js`/해당 배경 | 공격 로직과 독립, UI 가독성 |

`src/battle/modes/timing.js`, `src/battle/modes/cannon-guard.js`는 실제 계약 사례다. 새 모드는 `hitEnemy`, `hurtParty`, `setText` 등 제공된 공개 동작으로 결과를 돌려준다. 필요한 경우 공개 API를 최소 확장하고 호출부·공통 테스트를 함께 확인한다. 모드에서 HP나 `battle.state`를 직접 덮어써 승패 처리를 우회하지 않는다. 이벤트 리스너·음악·임시 캔버스는 종료/패배/재시도에 해제한다.

공통 파티의 쓰러짐·부활·전원 패배·재시도·보상은 새 기믹과 분리한다. 성공/실패/시간 초과/행동 중 적 사망/전원 쓰러짐/재시도에서 결과가 한 번만 적용되는지 본다. 필요한 입력은 기존 키보드·패드와 연결하고, 마우스 전용 조작은 도입 범위를 명시한다.

## 검증 근거

`tests/unit/mankatsuki-patterns.test.mjs`, `mankatsuki-reactivity.test.mjs`, `battle-modes.test.mjs`, `patterns.test.mjs`에서 변경한 계약을 찾는다. `tests/playtest/enemy.mjs <id> --pattern=N`은 지정 패턴 확인용이며 자연 순환·승리·재도전까지 봤다는 뜻이 아니다. 새 패턴은 경고/발사/회피/끝 프레임을 확인하고, 순환·격노를 바꿨다면 정상 진입 경로도 실제 입력으로 확인한다.
