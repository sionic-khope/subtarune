# 용준 상점 구매와 영구 강화

## Status

Accepted. 2026-09-13, BUILD114 사용자 요청에 따른 구현 결정.

## Context

마이야르호 라운지에서 소모품과 팀 영구 강화를 판매한다. 기존 저장은 `inventory`, `money`, `attack`, `hpBonus`, `partyHp`, `flags`의 최종 값을 기록한다. QA 이동은 저장을 읽지 않고 `stateFromFlags`로 새 상태를 만든다. 구매와 QA 복원에서 이 차이를 지켜야 중복 강화와 무료 구매가 생기지 않는다.

## Decision

`src/data/shops.js`의 `YONGJUN_SHOP`이 가격·설명·효과·구매 플래그의 원본이다. 에그타르트50원은 HP100, 위장약100원은 HP200 회복 소모품으로 이름 문자열을 기존 인벤토리에 추가한다. 씨알리스1000원은 공유 공격력+1, 바세린1500원은 공유 최대 HP 보너스+20을 즉시 적용한다. 강화 상품은 인벤토리에 들어가지 않는다.

`shopItemState(game, itemId)`는 `{ok, reason, item}`을 반환하는 읽기 전용 검사다. `reason`은 `null`, `unknown`, `sold_out`, `insufficient_money` 중 하나다. `purchaseShopItem(game, itemId)`만 실제 구매를 수행한다. 실패에는 변화·저장이 없고 성공에는 돈, 효과, 구매 플래그를 모두 적용한 뒤 `game.autosave()`를 한 번 호출한다. 취소 UI는 구매 함수를 호출하지 않는다.

바세린은 변경 전 각 인물의 현재 HP를 먼저 읽고, 공유 최대 HP와 현재 HP에 각각20을 더해 부족한 체력을 보존한다. 리더와 동료, 이탈했지만 HP 기록이 남은 동료를 포함한다. 이후 처음 합류한 동료는 기존 최대 HP 계산에서 공유 보너스를 받고 기본 최대 체력으로 시작한다.

세이브별 `shop_yongjun_cialis`, `shop_yongjun_vaseline`은 영구 품절 표시다. 방의 기존 바세린 관련 플래그와 무관하다. 이어하기는 기존 저장된 최종 스탯을 그대로 읽으며 효과를 재적용하지 않는다. `stateFromFlags`는 매번 기본값에서 스토리 버프를 계산한 뒤 실제 구매 플래그가 있는 상품의 스탯을 더하고 가격을 뺀다. 불완전한 개발 플래그의 음수 잔액은0으로 제한한다. 일반 라운지 QA는 구매 플래그를 자동으로 세우지 않는다. 소모품의 반복 구매·사용 이력은 최종 인벤토리/잔액 세이브에만 보존되며 스토리 플래그에서 추측하지 않는다.

## Consequences

저장 형식 변경 없이 현재/미래 팀원과 반복 로드에 동일한 규칙이 적용된다. UI는 구매 결과와 카탈로그만 표시하며 돈이나 스탯을 직접 수정하지 않는다. `Game.autosave()`의 상점 상태 허용은 통합부에서 처리해야 한다. 저장소 쓰기 실패에 대한 기존 자동저장의 동작은 유지한다.

## ADR Dependencies

없음. 기존 아이템 레지스트리, 파티 최대 HP 계산, 저장, QA 상태 복원을 사용한다.

## Engine Compatibility

자체 HTML5 Canvas2D / ES2022 모듈. 새 의존성, 엔진 API 또는 저장 버전 변경 없음. `tests/unit/shop.test.mjs`는 가격, 경계 잔액, 중복 구매, 현재/미래/복귀 동료, 직렬화 후 반복 구매, QA 복원을 검증한다.

## GDD Requirements Addressed

Foundational — 별도 GDD 요구사항 없음. BUILD114 사용자 지정 용준 상점의 가격과 세이브별1회 영구 강화 요구를 구현한다. 기존 스토리 어드벤처의 소모품 및 파티 전투 시스템을 연결한다.
