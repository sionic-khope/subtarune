# 용준 상점 구매·판매와 영구 강화

## Status

Accepted. 2026-09-13, BUILD114 구매와 BUILD116 판매·이벤트 가격 사용자 요청에 따른 구현 결정.

## Context

마이야르호 라운지에서 소모품과 팀 영구 강화를 판매한다. 기존 저장은 `inventory`, `money`, `attack`, `hpBonus`, `partyHp`, `flags`의 최종 값을 기록한다. QA 이동은 저장을 읽지 않고 `stateFromFlags`로 새 상태를 만든다. 구매와 QA 복원에서 이 차이를 지켜야 중복 강화와 무료 구매가 생기지 않는다.

## Decision

### BUILD301 · 구조 후 상점

`choimis_rescued` 이후 진열은 네 상품으로 교체된다. 더 강한 바세린은10원에 일행 최대 HP 영구+20, 더 강한 씨알리스는10원에 공격력 영구+1이다. 기존 이름별 효과를 유지하며 `shop_yongjun_strong_vaseline`, `shop_yongjun_strong_cialis`로 새 강화 단계를 각각 한 번만 살 수 있다. 예전 일반 강화 구매 플래그와 능력치는 유지되고, 일반 강화 버튼은 이 진열에 중복 노출하지 않는다. 강화 상품은 인벤토리에 들어가지 않는다.

핫도그는 한 명 HP150, 기름떡볶이는 현재 일행 전체 HP100을 회복한다. 둘 다10원 반복 구매·5원 판매이며, 사용하면 한 개만 소모한다. 필드와 전투가 `src/core/item-use.js`의 실제 소비 경로를 사용한다. 회복은 개인 최대 HP에 제한되며 전투의 기존 쓰러진 동료 회복 규칙을 유지한다. 전체 회복 확인에서는 전원을 강조하고, 확인 전 취소에는 수량·HP 변화가 없다.

BUILD300에서 잘못 소모품으로 판매했던 두 이름은 저장 인벤토리 문자열이므로 제품ID 변경만으로 고칠 수 없다. 이어하기 시 `normalizeItemNames`가 남은 더 강한 바세린을 핫도그, 더 강한 씨알리스를 기름떡볶이로 이름만 바꾼다. 개수·순서·나머지 아이템·돈·능력치·구매 플래그는 보존하며, 반복 로드해도 추가 변환이나 강화가 없다. QA 상태 재구성은 옛 단계와 새 단계의 구매 플래그를 각각 한 번 합산한다.

`tests/unit/shop301.test.mjs`, `item-use.test.mjs`가 신규 단계 중복 구매·기존 단계 보존·수량·대상별 회복·전멸 동료 회복·최대 HP 제한·옛 저장 이름 변환을 검증한다. 구조 전 상점 계약은 아래와 같이 그대로다.

### 기존 일반 상점

BUILD118: 구매 확인은 **예**가 기본이며 좌우로 아니오를 선택하거나 X로 취소할 수 있다. 판매 확인은 기존 **아니오** 기본을 유지한다. 구매 성공에만 원본 `snd_buyitem` 기반 `shop_buy` 효과음을 재생하며 가격·저장·강화 처리는 바꾸지 않는다.

`src/data/shops.js`의 `YONGJUN_SHOP`이 가격·설명·효과·구매 플래그의 원본이다. 에그타르트50원은 HP100, 위장약100원은 HP200 회복 소모품으로 이름 문자열을 기존 인벤토리에 추가한다. 씨알리스와 바세린은 각각10원이며 `event:true`로 노란 `이벤트!` 배지를 표시한다. 씨알리스는 공유 공격력+1, 바세린은 공유 최대 HP 보너스+20을 즉시 적용한다. 강화 상품은 인벤토리에 들어가지 않는다. 기존 상품 ID와 구매 플래그를 유지한다.

`shopItemState(game, itemId)`는 `{ok, reason, item}`을 반환하는 읽기 전용 검사다. `reason`은 `null`, `unknown`, `sold_out`, `insufficient_money` 중 하나다. `purchaseShopItem(game, itemId)`만 실제 구매를 수행한다. 실패에는 변화·저장이 없고 성공에는 돈, 효과, 구매 플래그를 모두 적용한 뒤 `game.autosave()`를 한 번 호출한다. 취소 UI는 구매 함수를 호출하지 않는다.

상점 첫 화면은 산다/판다/나가기다. `YONGJUN_RESALE_PRICES`는 판매 가격 원본으로 상점 소모품 구매가의 절반(소수점 버림)을 계산한다. 현재 에그타르트25원, 위장약50원이며 비매품 바나나10원, 먼지1원은 사용자가 정한 가격이다. UI에서 가격을 따로 정의하지 않는다. `ITEMS`에 등록된 `kind:'plain'`이면서 판매가가 있는 아이템만 판다. 중요 아이템과 미등록 이름은 직접 판매 함수를 호출해도 거부한다.

`saleItemState(game, inventoryIndex)`는 `{ok, reason, item, name, price, inventoryIndex}`를 반환하는 읽기 전용 검사다. `item`은 아이템 레지스트리 정의이고 `name`은 인벤토리 이름이다. `reason`은 `null`, `invalid_index`, `unknown`, `key_item`, `unsellable` 중 하나이며 잘못된 인덱스에는 아이템 필드를 생략한다. 실패에는 가격을 반환하지 않는다. UI는 필터링된 목록 순번이 아닌 원본 인벤토리 인덱스를 전달한다. `sellShopItem(game, inventoryIndex)`는 실행 시 다시 검사하고 해당 인덱스 한 개만 제거한 뒤 돈을 더해 한 번 자동저장한다. 같은 이름의 다른 아이템, 스토리/구매 플래그, 파티 및 영구 스탯은 바꾸지 않는다. 취소와 판매 실패에는 변화·저장이 없다.

바세린은 변경 전 각 인물의 현재 HP를 먼저 읽고, 공유 최대 HP와 현재 HP에 각각20을 더해 부족한 체력을 보존한다. 리더와 동료, 이탈했지만 HP 기록이 남은 동료를 포함한다. 이후 처음 합류한 동료는 기존 최대 HP 계산에서 공유 보너스를 받고 기본 최대 체력으로 시작한다.

세이브별 `shop_yongjun_cialis`, `shop_yongjun_vaseline`은 영구 품절 표시다. 방의 기존 바세린 관련 플래그와 무관하다. 이어하기는 기존 저장된 최종 잔액·스탯을 그대로 읽으며 할인 차액 환급이나 효과 재적용을 하지 않는다. `stateFromFlags`는 매번 기본값에서 스토리 버프를 계산한 뒤 실제 구매 플래그가 있는 상품의 스탯을 더하고 현재 카탈로그 가격을 뺀다. 불완전한 개발 플래그의 음수 잔액은0으로 제한한다. 일반 라운지 QA는 구매 플래그를 자동으로 세우지 않는다. 소모품의 반복 구매·사용·판매 이력은 최종 인벤토리/잔액 세이브에만 보존되며 스토리 플래그에서 추측하지 않는다.

## Consequences

저장 형식 변경 없이 현재/미래 팀원과 반복 로드에 동일한 규칙이 적용된다. UI는 거래 결과와 카탈로그만 표시하며 인벤토리·돈·스탯을 직접 수정하지 않는다. `Game.autosave()`의 상점 상태 허용은 통합부에서 처리한다. 저장소 쓰기 실패에 대한 기존 자동저장의 동작은 유지한다.

## ADR Dependencies

없음. 기존 아이템 레지스트리, 파티 최대 HP 계산, 저장, QA 상태 복원을 사용한다.

## Engine Compatibility

자체 HTML5 Canvas2D / ES2022 모듈. 새 의존성, 엔진 API 또는 저장 버전 변경 없음. `tests/unit/shop.test.mjs`는 가격, 경계 잔액, 중복 구매, 현재/미래/복귀 동료, 직렬화 후 반복 구매, QA 복원, 단일 아이템 판매, 중요 아이템 차단, 잘못된 인덱스와 거래 저장을 검증한다.

## GDD Requirements Addressed

Foundational — 별도 GDD 요구사항 없음. BUILD114/116 사용자 지정 용준 상점의 구매·판매 가격과 세이브별1회 영구 강화 요구를 구현한다. 기존 스토리 어드벤처의 소모품 및 파티 전투 시스템을 연결한다.
