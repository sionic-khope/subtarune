# 따듯한비데 v2 이미지 전달

키가 큰 회색 갑옷 캐릭터와 큰 도끼를 유지한 **자산 전달용 묶음**이다. 캐릭터·적·맵·전투 등록은 하지 않았다. 아군/적군 소속과 능력은 미정이며, 전투 대기 4장만 있고 공격·달리기·피격·사망 모션은 없다.

## 파일과 좌표

원본·참고 그림·프롬프트·프레임별 좌표는 [원본 폴더](../../assets/source/warm-bidet-v2/)와 [manifest.json](../../assets/source/warm-bidet-v2/manifest.json)에 있다. `battle-shaft-fix-prompt.txt`는 현재 전투 원본에 적용한 도끼 자루 수정 이력이며 추가 생성 명령이 아니다.

| 용도 | 투명 PNG | 격자 / 셀 크기 | 순서 |
|---|---|---|---|
| 이동 | [warm-bidet-walk.png](../../assets/sprites/warm-bidet-v2/warm-bidet-walk.png) | 4×4 / 240×312 | 정면→왼쪽→오른쪽→뒤, 행마다 4장 |
| 전투 대기 | [warm-bidet-idle.png](../../assets/battle/warm-bidet-idle.png) | 2×2 / 470×528 | 좌상→우상→좌하→우하, 모두 오른쪽 |

이동 단일 프레임은 `assets/sprites/warm-bidet-v2/warm-bidet-walk-0.png`부터 `-15.png`, 전투 단일 프레임은 `assets/battle/warm-bidet-idle-0.png`부터 `-3.png`다. 전체 이동 시트는 960×1248, 전투 시트는 940×1056이다. 단일 파일 전체가 프레임 하나이며 배경은 RGBA 투명이다.

`rect`는 `[x,y,width,height]`, `bounds`와 공통 crop은 `[left,top,right,bottom)`이다. 원본 셀 좌표의 기준은 시트 좌상단, crop/opaque bounds는 각 원본 셀 좌상단, 출력 pivot은 각 프레임 좌상단이다. `manifest.frames[].source_rect`, `source_pivot`, `pivot`, `atlas_rect`를 함께 사용한다.

| 원본 | 열 범위 [start,end) | 행 범위 [start,end) |
|---|---|---|
| 이동 1122×1402 | 25–284, 298–554, 570–828, 844–1100 | 58–369, 382–688, 702–1008, 1022–1339 |
| 대기 1254×1254 | 60–615, 639–1194 | 84–635, 659–1196 |

이동은 모든 셀에 공통 crop `[12,5,244,309]`, 대기는 `[65,15,527,535]`를 사용한 뒤 사방에 4px 투명 여백을 더한다. 확대·축소·색 평균·양자화·재그리기는 없다. 원본 셀별 인물 위치 차이와 자세 변화는 유지한다.

이동의 출력 pivot은 정면 `[128,306]`, 왼쪽 `[140,300]`, 오른쪽 `[106,300]`, 뒤 `[106,308]`이다. 방향별 첫 프레임의 양발 가운데와 공통 바닥선을 기준으로 정했으며 같은 방향의 4장에는 동일 pivot을 적용한다. 발 움직임마다 독립적으로 중앙/하단 정렬하지 않는다. 대기의 출력 pivot은 순서대로 `[169,524]`, `[165,524]`, `[169,522]`, `[165,522]`로, 원본 열·행 간 위치 차이를 보정하는 양발 기준점이다. pivot은 추출용 권장값이며 실제 장면 루프는 아직 확인하지 않았다.

## 연결할 세션에서 확인할 계약

현재 `src/core/gfx.js`의 필드 시트는 엔진 행 순서 **down/up/left/right**와 2x 해상도를 전제로 한다. 이번 이동 출력은 원본 순서 **down/left/right/up**이고 원본 픽셀 밀도를 보존한 큰 셀이다. `assets/sprites/<등록 ID>.png`에 그대로 덮어쓰거나 이름만 등록하지 않는다. 소비 시 manifest 순서·pivot·배율을 지원하거나, 후속 변환 시 행을 `[0,3,1,2]`로 재배열한다. 기존 `sideWalk`의 상체/하체 연결 위치도 이 캐릭터에 그대로 복사하지 않는다.

현재 `src/battle/battle.js`의 `drawEnemy`는 `image` 단일 PNG와 `pivot`을 지원한다. 정지 이미지로 시험할 때는 `warm-bidet-idle-0.png` 전체와 `[169,524]`를 사용할 수 있다. `sheet` 분기는 셀 높이를 절반으로 표시하고 하나의 `row`에서만 프레임을 선택하므로, 이번 2×2 대기 시트를 연결하면 네 장의 순서와 개별 pivot을 표현하지 못한다. 애니메이션 소비는 네 프레임을 명시적으로 지원해야 한다. 최신 브랜치에서 이 계약이 바뀌었는지 먼저 확인한다.

전투 원본은 **오른쪽 방향**이다. 화면 오른쪽의 적이 왼쪽을 보게 하려면 소비 코드에서 좌우 반전을 선택하고 pivot도 `frameWidth - pivotX`로 변환한다. 이름이나 무기만 보고 적군으로 등록하지 않는다. 기존 `battle-sprites.js`/`battle-action.js` 아군의 접근→공격→복귀 동작에 이번 idle을 공격 프레임으로 넣지 않는다.

원본 몸체 높이는 이동 약 280px, 대기 약 500px다. 배율은 도끼까지 포함한 bbox 폭이 아닌 **발→머리 높이**로 장면의 다른 인물과 맞춘다. 예를 들어 몸체 높이를 90px로 표시하려면 이동 약 `90/280`, 대기 약 `90/500`부터 확인한다. 이는 확정 게임 크기가 아니다. 도끼가 넓다고 몸을 별도로 작게 만들지 말고, 화면에서 최근접 샘플링(`imageSmoothingEnabled=false`)을 사용하며 원본 PNG는 유지한다. 권장 시작 시간은 이동 0.14초/장, 대기 0.25초/장이며 실제 루프와 입력 연결은 후속 작업이다.

## 재현과 확인 범위

저장소 루트에서 실행한다. 의존성 버전은 스크립트에 고정했다.

```bash
uv run assets/source/warm-bidet-v2/export.py
tools/dev/check.sh
```

추출기는 기존 `tools/sprites/slice_sheet.py:key_cell`을 재사용하여 가장자리에 연결된 배경을 제거한다. 이동 시트의 도끼 연결부·팔/몸 사이에 닫힌 보라색 배경 틈이 남아, 육안 확인한 프레임별 시드에서 같은 배경 후보 색 범위만 flood fill하여 알파를 추가 제거했다. 팔레트 전체를 일괄 삭제하거나 남은 불투명 픽셀 색을 바꾸지 않는다. 시드 좌표와 프레임별 제거 수는 manifest에 있다. 추가 정리 전 [중간 시트](../../assets/source/warm-bidet-v2/intermediate/walk-edge-keyed.png)도 보존했다. 원본의 외곽 혼색을 모두 재색칠한 결과는 아니다.

정적 원본·투명 시트 육안 확인, 전체 20프레임의 원본 RGB 보존·이진 알파·여백·좌표 정합, 두 번 재생성한 파일 해시 일치를 확인한다. 게임 등록·장면 배치·공격 모션·실제 루프·플레이테스트는 이번 묶음의 완료 범위가 아니다. 기존 게임 서버도 재기동하지 않는다.
