# 전투 개발 세션용 이미지 전달

이 PR의 목적은 **현재 만들고 있는 전투 시스템에 아래 미니언 이미지를 쓰고, 무기 상자에는 아래 상자 이미지를 쓰도록 전달하는 것**이다. 런타임·맵·컷신·밸런스는 변경하지 않는다. 소비 코드는 후속 전투 개발 세션에서 연결한다.

## 먼저 확인할 상태

확인 기준은 main `eedd409`다. 이 시점에는 아군 전투 모션 미리보기와 청록숲3 공구상자 컷신이 커밋되어 있다. 별도 로컬 세션에서 `src/battle/`, `src/data/enemies.js`, `src/data/items.js`와 전투 진입 연결을 개발 중인 것도 확인했지만, 그 미커밋 작업은 이 PR에 가져오지 않았다. 이 문서만 보고 전투 엔진이 없다고 재작성하거나 완성됐다고 판단하지 말고, **적용할 브랜치의 최신 코드부터 확인한다.**

## 사용할 이미지

모두 RGBA 투명 PNG이며 **각 파일 전체가 정지 프레임 1개**다. 원점은 좌상단, pivot은 이미지 안의 발/바닥 기준 좌표다. 기계 판독용 규격과 생성 원본 경로는 [manifest.json](../../assets/source/combat-props-v1/manifest.json)에 있다.

| 용도 | 파일 | 크기 | 방향 | pivot |
|---|---|---|---|---|
| 레드 근접 미니언, 필드 | [cs-red-front.png](../../assets/enemies/cs-red-front.png) | 48×48 | 정면 | 24,44 |
| 블루 근접 미니언, 필드 | [cs-blue-front.png](../../assets/enemies/cs-blue-front.png) | 48×48 | 정면 | 24,44 |
| 레드 근접 미니언, 전투 | [cs-red-battle-left.png](../../assets/enemies/cs-red-battle-left.png) | 64×64 | 왼쪽 | 32,60 |
| 블루 근접 미니언, 전투 | [cs-blue-battle-left.png](../../assets/enemies/cs-blue-battle-left.png) | 64×64 | 왼쪽 | 32,60 |
| 검·칼·마법봉이 든 열린 나무상자 | [weapon_box_open.png](../../assets/props/weapon_box_open.png) | 64×64 | 앞/약간 위 | 32,60 |

미니언은 LoL 레드·블루 근접 CS를 참고한 생성 도트다. 전투에서는 화면 오른쪽에 서서 왼쪽의 아군을 본다. 필드용은 정면만 제작했고 걷기·공격·피격·사망 프레임은 없다. 정지 스프라이트를 위치 이동시키는 것은 가능하지만 실제 걷기 애니메이션으로 취급하지 않는다.

상자는 네모 나무상자에 열린 평평한 뚜껑, 장검·단검·파란 구슬 마법봉이 보이는 단일 소품이다. 닫힌 상태·빈 상자·열리는 모션은 포함하지 않는다. 사용자에게 최종 위치를 확인한 뒤 배치한다. 그림의 단검은 **경섭 장비를 바꾸는 지시가 아니다**. 아군 장비는 형섭=칼, 경섭=양손도끼, 빠맨=파란 구슬 한손 마법봉을 유지한다.

## 연결할 때

1. **필드 미니언**: 청록숲3 컷신 [teal3_toolbox.js](../../src/data/cutscenes/teal3_toolbox.js)의 CS 등장 부분을 확인한다. 기존 `assets/sprites/cs.png`는 4×4 캐릭터 시트다. 이번 48×48 PNG를 그 파일에 덮어쓰면 로더가 다시 4분할하여 잘못 자른다. 최신 엔진의 단일 이미지 경로를 쓰거나 정지 프레임 계약을 명시적으로 지원한 뒤 레드/블루를 각각 연결한다. 기존 등장 ID·점프·이동·컷신 순서는 유지한다.
2. **전투 적**: 최신 적 정의와 렌더러에 `*-battle-left.png`를 연결한다. 원본 사각형은 `[0,0,64,64]` 하나이며, 이미 왼쪽을 보므로 기본 상태에서 다시 반전하지 않는다. 바닥 기준 좌표에 pivot을 빼서 그린다. 별도의 공격 애니메이션이 없는 상태에서 아군의 4프레임 설정으로 분할하지 않는다.
3. **무기 상자**: 위치가 확정되면 [teal3.json](../../assets/maps/teal3.json)의 `toolbox` 같은 소비 대상과 해당 맵 생성기를 함께 갱신한다. 현재 `toolbox.png`의 크기와 그림 오프셋은 새 64×64와 다르다. `image`만 바꾸지 말고 그림 `ix/iy` 또는 `scale`과 바닥 pivot을 맞춘다. 충돌·상호작용 영역은 상자 몸통/밑동에 맞추며 위로 열린 뚜껑 전체를 벽으로 만들지 않는다. 현재 상자 ID·대사·아이템 배분 로직은 유지한다.

최종 PNG는 이미 배경 처리와 최근접 추출을 마친 파일이다. 마젠타 재처리·추가 양자화·평균 축소 없이 사용하고, Canvas는 `imageSmoothingEnabled=false`로 그린다. 장면의 배율은 최신 캐릭터 크기에 맞춰 정하되 원본 파일을 다시 축소 저장하지 않는다.

### 개발 중인 전투 코드와 접점

2026-09-10 로컬 미커밋 코드에서 확인한 참고이며, 후속 세션의 최신 구현과 대조한 뒤 사용한다.

- `src/data/enemies.js`: `image`는 단일 PNG, `sheet`는 필드 시트 분할용이다. 새 전투 PNG는 `image`로 연결하고 해당 적의 기존 `sheet`를 함께 유지하지 않는다. 현재 렌더러는 `sheet`가 있으면 그 경로의 분할 처리를 우선한다.
- 레드/블루를 둘 다 쓰려면 적 정의를 별도 ID로 구분하고, `teal3_toolbox.js`의 `enemies:['cs','cs']`를 그 ID에 연결한다. 색상별 능력치 차이는 이 PR에서 정하지 않는다.
- `src/battle/battle.js drawEnemy`의 단일 이미지 분기는 전체 이미지 하단을 기준으로 그린다. 이번 PNG의 바닥 pivot은 y60이고 전체 높이는64이므로, 실제 발을 기준점에 놓으려면 pivot 지원 또는 표시 오프셋으로 `4×scale` 여백을 보정한다. 시트 분기는 `크기/2×scale`, 단일 이미지는 `크기×scale`이므로 기존 `cs.scale`을 그대로 복사하기 전에 실제 크기를 확인한다.
- 필드 등장 개체 ID는 `cs1`/`cs2`다. `sprite:'cs', facing:'left'`로 생성되지만 이번 필드 이미지는 사용자 요청대로 정면뿐이다. 단일 이미지 지원 시에도 정면을 유지한다.
- 상자 맵 생성기는 `tools/maps/teal.py`의 teal3 구간이다. 아이템 레지스트리는 이미지 로더가 아니므로 상자 그림 교체만으로 `items.js`를 변경할 필요는 없다.

## 이미 있는 아군 전투 작업

- [battle-sprites.js](../../src/data/battle-sprites.js): 형섭·경섭·빠맨의 대기/공격/무기 든 달리기 원본 경로, 프레임 영역, 발 pivot, 배율, 시간. 아군 시트는 균등 분할 대신 이 메타데이터를 사용한다.
- [battle-action.js](../../src/ui/battle-action.js): 상대 앞으로 접근 → 공격 → 원래 자리 복귀 시퀀스.
- [battle-preview.js](../../src/ui/battle-preview.js): 시트 배경 처리·프레임 캐시와 테스트룸 미리보기. `?map=test&battle=1`에서 확인한다.

원래 요청은 **상대에게 달려가 상대 앞에서 공격하고 돌아오는 턴제 연출**이다. 이 PR이 HP·대미지·턴·아이템 효과를 새로 정하지는 않는다. 개발 중인 전투 엔진이 위 모션 기반을 이미 재사용한다면 그 연결을 유지한다.

## 연결 완료를 판단할 최소 확인

- 필드에서 레드/블루 모두 몸 전체가 보이고 정면 1장이 4등분되지 않는다.
- 전투에서 적이 왼쪽을 보고 발이 기준점에 붙는다. 아군 접근→공격→복귀가 기존 전투 흐름과 이어진다.
- 상자 앞 상호작용이 닿고, 무기·뚜껑이 잘리지 않으며 기존 이벤트 순서가 유지된다.
- 맵 생성기를 다시 실행해도 선택한 파일 경로와 배치가 유지된다.

이 PR에서는 파일·규격·문서 링크와 기존 전투 모션 유닛 테스트만 확인한다. 위 게임 연결 시나리오는 후속 적용 작업의 완료 기준이지 이미 끝났다는 보고가 아니다.
