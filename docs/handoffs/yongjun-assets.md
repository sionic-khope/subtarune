# 용준 스프라이트 사용 지침

용준의 필드 이동에는 **[assets/sprites/yongjun.png](../../assets/sprites/yongjun.png)를 사용한다.** 기존에 생성한 용준 v1에서 투명 배경과 엔진 행 순서로 추출한 4방향 × 4프레임 시트다. 캐릭터·맵·파티·적 등록, 능력치, 전투 이미지와 대화창 초상화는 이번 전달에 포함되지 않는다.

## 파일 규격

- 전체 PNG: **248×344, RGBA**, 투명/불투명 알파는 0/255.
- 셀: **62×86**, 4열×4행. 위에서부터 **down / up / left / right**, 각 행은 왼쪽부터 프레임 **0, 1, 2, 3**. 정지는 0번이다.
- 셀 영역: `[열×62, 행×86, 62, 86]`. 좌상단이 원점이고 엔진용 하단 중앙 pivot은 **[31,86]**이다.
- 현재 필드 로더는 2x 시트로 읽는다. 기본 논리 셀은 31×43이며 기존 `CHAR_SCALE`이 추가 적용된다. 48×48 고정 셀로 나누거나 원본 행 순서로 다시 뒤집지 않는다.

신발 밑변은 프레임에 따라 y85 또는 y86이며 [manifest](../../assets/source/yongjun-v1/manifest.json)에 기록했다. 기존 변환기의 하단 정렬 때문에 8셀은 마지막 픽셀 행에 신발이 닿는다. 원본은 모든 셀 안에 전신이 들어 있고, 출력은 동일 공통 crop의 최근접 변환과 일치한다. 발을 한 장씩 다시 바닥에 맞춰 원본의 높이 차이를 지우지 않는다.

## 게임에 연결할 때

1. 적용 브랜치의 `src/data/characters.js`, `src/main.js`의 이미지 사전 로드, `src/world/world.js`의 `characterSprite`를 확인한다. 현재 사전 로드는 등록된 캐릭터/팔레트 ID를 순회하므로 PNG 추가만으로 용준이 등장하지 않는다. 후속 구현에서 이름 `용준`과 ID `yongjun`을 등록하고 이 파일을 필드 시트로 사용한다. `still` 단일 프레임 경로는 사용하지 않는다.
2. **옆걷기 보정을 용준 셀에서 측정한다.** 프로젝트 규칙은 상체·머리·팔을 고정한 `기본 → 발 A → 기본 → 발 B`다. 이번 PNG는 생성 원본의 네 자세를 보존해 상체와 팔 변화도 포함한다. 후속 연결 시 양쪽 옆모습의 하체 연결선과 발 영역을 확인하여 `sideWalk.legY/legFrames` 또는 `feetY/splitX/stride`를 정하고, 접합부·신발 끝·정지 복귀를 실제 로더로 확인한다. 다른 캐릭터의 76/82px 연결선이나 쥰희의 발 설정을 복사하지 않는다. 이번 전달은 용준용 `sideWalk` 값이나 보정된 3포즈 루프를 확정하지 않는다.
3. 등장 위치·역할·대사·전투 참가 여부는 후속 요청에 맞춘다. 이동 시트를 전투 공격이나 초상화로 간주하지 않는다.

용준은 짧고 둥근 검정 머리, 넓은 볼, 가는 눈, 작은 코, **치아가 보이는 웃는 입**, 안경 없는 얼굴을 유지한다. 형섭의 입 제거 규칙을 적용하지 않는다. 살구 피부·흰 반팔·남색 반바지·검은 신발은 흑백 상반신 원본을 보완한 v1 제안이며 영구 확정 설정이 아니다.

## 보존·재추출·검증

[원본 시트](../../assets/source/yongjun-v1/walk-sheet.png), [사용자 레퍼런스](../../assets/source/yongjun-v1/reference.png), [생성 프롬프트](../../assets/source/yongjun-v1/prompt.txt)를 보존한다. 좌표·해시·동일 방향 공통 crop은 [manifest.json](../../assets/source/yongjun-v1/manifest.json)에 있다. 저장소 루트에서 실행한다.

```bash
uv run --with pillow --with numpy -- python tools/sprites/slice_sheet.py --sprites-only assets/source/yongjun-v1/walk-sheet.png yongjun
shasum -a 256 assets/sprites/yongjun.png
```

예상 SHA-256: `fb9fce00fc20cd626a61ecdd3ebf888ccc4ac4990a1c27dbcf6f36a8c9b65368`.
완성 시트를 변환기 입력으로 다시 넣지 않는다. 기존 도구로 가장자리 연결 배경만 제거하고 같은 방향 네 장에 공통 crop·1/3 최근접 샘플링을 사용했다. 색 양자화·재그림·개별 프레임 크기 보정은 하지 않았다.

검증: 16셀의 알파·행 순서·공통 crop 결과 일치와 동일 명령 재추출을 확인했다. `tools/dev/check.sh`의 문법·단위 테스트 338개·맵 동기화 검사가 통과했다. 실제 브라우저에서 기존 `characterSprite`가 16프레임을 픽셀 변경 없이 분리하고 62×86/2x로 읽는 것, `Character.animate`의 0→1→2→3→0 재생과 정지 시 0번 복귀, 페이지 오류 없음을 확인했다. 이미지에서 얼굴·방향·전신·신발을 확인했다. 이는 자산 로더 검증이며 용준의 맵 배치나 보정된 옆걷기 완료를 뜻하지 않는다.
