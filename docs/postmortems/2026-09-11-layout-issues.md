## 공통 원인
1. **보이는 영역을 숫자로 안 갖고 있었다.** 대화 중 230px, 전투 246px, 프로브 19px, 히트박스 24×16 같은 예산이 코드 곳곳의 리터럴이라 맵·컷신을 짤 때 참조하지 않았다 → `src/core/layout.js` 로 모으고 `layout.test` 가 리터럴과 대조.
2. **자리를 '타일 좌표'로만 두고 '그려지는 사각형'을 계산하지 않았다.** 히트박스와 그림은 다르고(나무 밑동은 그림 한 칸 아래, 정지 그림은 발 기준 위로), 겹침·잘림은 그림 사각형끼리 재야 보인다 → `tests/playtest/lib/layout.mjs` (`rectsOf`, `enemyRects`, `inside`, `overlap`).
3. **스크린샷을 '나오는지'로만 봤다.** 잘림(가장자리 4곳), 가림(대화창·패널·앞 소품), 간격을 항목으로 보지 않았다 → 스킬에 스크린샷 체크 항목 명시.
4. **한 번 고친 규칙이 데이터 감사로 남지 않았다.** 같은 실수를 다음 생성기에서 반복 → `maps-layout.test.mjs` 4개 감사(모든 맵에 적용, 기존 맵도 통과하게 생성기 수정).

## 규칙 (스킬·CLAUDE.md 반영)
- 크기·자리는 **`src/core/layout.js` 예산 안에서 사각형으로 계산**하고, 감사(`node --test`)와 프레이밍 검사(플레이테스트)에 넣은 뒤 스크린샷을 본다.
- 스크린샷 체크: ① 가장자리 4곳에 걸린 그림 ② 대화창·패널·앞 소품에 가려진 캐릭터 ③ 캐릭터끼리 겹침 ④ 대화 간격(64px) ⑤ 떠 있는 느낌(그림자·밑동).
- 소품 열과 캐릭터 자리 열은 겹치지 않게(정렬 자리 ±1열은 소품 금지).
- 큰 캐릭터(≥ 150px)는 카메라를 화자별로 옮긴다(`teal9_boss.js` CAM_RED/CAM_BLUE).
