# 최미스 최종전·구조 연속성 검수

BUILD300 제작 중 확인한 구현 오류와 예방 기준이다. 최종 승인 여부는 별도 증거 장부를 따른다.

## 실제로 고친 부분

- 손을 올리는 그림과 꽃 모임 중심이 다른 기준점이었다. 원본 프레임의 손/발 피벗을 측정해 손으로 모인 뒤 몸을 감싸도록 바꿨다. 적의 x에 임의 숫자를 빼는 것으로 “감싼다”를 구현하지 않는다.
-4초 자동 충전 요구는 짧은 일반 완충탄의 즉시 발사와 다르다. 진행0→1, 오라 수렴/크기, 소유 충전음의4초 유지, 발사 직전 정리를 각각 확인한다. 사망 완료는 타격 후 연기·기본 모습·낙하까지 끝난 시점이다.
-원경 구조의 점이 제트기와 닿기 전에 사라질 수 있었다. 집게 화면 앵커의 접촉 시각을 사라짐·효과음과 공유한다. 수치상 catchCount 증가만으로 구조가 읽힌다고 판정하지 않는다.
-조종사와 승객을 기체 위에 그대로 그리면 붙여놓은 그림처럼 보인다. 승인 PNG의 조종석 하단과 집게 앞 난간을 전경으로 다시 그려 실제 가림을 유지한다. 새로운 손그림으로 선체를 덧칠하지 않는다.
-귀환 상점 회복을 검사하려고 main.js 메서드 소스를 잘라 VM에서 실행한 테스트는 구현에 과하게 결합돼 있었다. 실제 메뉴 입력의 구매·대상 선택·회복·소비 검사로 옮기고 기존 아이템/상점 단위검사는 유지한다.

## 다음에도 유지할 기준

라운지 브리핑을 추가한 뒤 실제 화면에서 봉인 최미스의 머리가 위에 잘리고 문이 보이지 않는 투척 구도를 발견했다. 투척은 별도 문 전체 구도로 보여 주고 대화 구도는32px 올렸다. 일행 느낌표가 같은 열의 쥰희 몸에 겹치는 문제는 쥰희의 기본 배치를32px 위로 조정했다. 말풍선·느낌표의 소유자가 맞다는 상태값만으로 주변 배우와의 겹침까지 통과시키지 않는다.

쥰희의 말 끊기 웃음은 정상 진행에서는 멈췄지만 타이틀/맵 중단에는 소유 핸들이 남을 수 있었다. 스크립트 소유와 기존 중단 경로를 연결하고 같은 정리를 재사용했다. 자연 종료와 중간 취소는 각각 검사한다.

구조 종료의 `{map, spawn, bgm:false}`가 음악 노드 분기에 먼저 잡혀 맵 이동을 건너뛰었다. 맵 옵션과 독립 음악 명령을 구분하도록 공통 DSL을 고쳤고 실제 makeWaiter 회귀검사를 추가했다. 대사가 전부 재생됐다는 사실만으로 귀환 성공을 주장하지 않는다. 마지막 mapId·조작 가능·저장 상태를 함께 검사한다.

전투 HP 하한, 현재 패턴 정리, 최종전 종료, 시네마틱 종료, 승리 보상, 구조 완료 단계는 서로 다른 경계다. 그중 하나가 됐다고 나머지를 앞당기지 않는다. 실제 장면의 직전·중간·직후를 캡처하고 저장/재입장과 파티 보행까지 확인한다. 테스트 수나 예전 빌드 PASS는 새 장면의 미적 완성도나 사용자 만족을 대신하지 않는다.
