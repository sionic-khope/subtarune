# 포스트모텀: 오브제 지역 자산 오선택과 바론 연출 검증 누락 (2026-09-12)

## 사건과 영향

obj3 진입로와 obj4 바론 둥지를 만들면서 오브제 지역 대신 옛 허공 지역의 바닥·절벽·배경을 사용했다. 사용자의 “보라색 공허 느낌”을 분위기 요청이 아니라 지역 전체 교체로 해석했다. 사용자가 지적하자 처음에는 색상 취향을 되물어, 실제 문제인 잘못된 자산 재사용을 바로 인정하지 못했다.

|---|---|---|

## 원인

- **자산 선택 실패:** “보라”라는 단어에 끌려 쉽게 쓸 수 있는 옛 세트를 택했다. 인접 obj1/obj2의 실제 렌더와 사용 파일을 먼저 비교하지 않았다. 올바른 지역 표를 읽어 놓고도 작업의 구체적인 자산 선택에 적용하지 않았다.
- **위임·검증 기준 실패:** 부모가 잘못 고른 환경을 작업자에게 전달했다. 이후 검증도 그 초안을 기준으로 프레임·좌표·파일 존재·완주 여부만 주로 보았다. 자체 작성 DESIGN의 일치나 여러 PASS가 사용자 의도와의 일치를 대신하지 못한다.
- **시간 축 누락:** 유충이 “옆에 도착했다”만 확인하고 그 전에 보이면 안 된다는 조건을 확인하지 않았다. 등장 시간 숫자를 구현한 것과 “팍”이라는 체감을 구현한 것을 혼동했다.
- **소리의 의미 누락:** 공용 효과음이 재생된다는 사실만 보고, 누가 어떤 공격을 하는 소리인지 구분하지 않았다.
- 사용자 설명 부족이나 자산 부재 때문이 아니다. 구현·자산 선정·리뷰를 맡은 Codex의 오류다.

## 재발 방지 적용 위치

- 실행 절차의 단일 기준: `.claude/skills/map/SKILL.md`의 “지역 자산 연속성”.
- 컷신의 등장 전 노출·등장 중 이동·도착과 충격 타이밍: `.claude/skills/cutscene/SKILL.md`의 “연출의 사전 조건”.
- `CLAUDE.md`에서 맵 확장·분위기 변경 시 위 공통 절차를 읽도록 연결한다. Codex/Claude가 같은 원본을 읽는다.
- 검증을 무겁게 늘리는 조치가 아니다. **인접 맵 한 장과 결과 한 장의 실제 자산 비교**, **영향받은 비트의 전/중/후 짧은 재생**을 기존 검사보다 먼저 한다. 관계없는 전체 게임·반복 리뷰로 이 실패를 덮지 않는다.
- 재사용 자체를 금지하지 않는다. 현재 지역에 맞는 최신 자산은 재사용하고, 새 전용 바닥·효과가 필요한 경우에는 그 요구를 별도로 제작한다.

## 수정 범위와 상태

obj3은 오브제 물길·숲 바닥·나무·원경으로 복구한다. obj4는 같은 지역의 외곽을 유지하면서 전용 젖은 바위 바닥, 소폭 줄인 가시 둘레를 사용한다. 유충은 처음 숨기고 화면 밖 왼쪽에서 오른쪽으로 진입한다. 바론은 더 큰 머리의 새 시트와 짧은 분출·보라 돌풍, 전용 타격음을 적용한다.

이 문서는 작업 브랜치 수정의 원인과 기준이다. main 병합·배포 완료를 뜻하지 않는다. 최종 재생 확인 결과는 해당 작업 기록에서 별도로 갱신한다.
