## 내부에서 잡은 것 (사용자에게 안 갔지만 같은 결의 실수)
- **패치 스크립트가 파일을 중복시켰다**: 파이썬으로 `battle.js` 의 세 구간을 바꾸며 `s[:a] + NEW + s[b:]` 를 썼는데 두 번째 앵커 `b` 가 `a` 보다 **앞**에 있어서 파일 뒷부분이 두 번 붙었다(`drawHpStrip` 두 개). `node --check` 는 통과(문법상 멀쩡) → 메서드 이름 grep 으로 발견, `git checkout` 뒤 `assert a < b` 넣고 다시. 
- **테스트 한 줄짜리 문장에 `//` 주석**을 끝에 붙였다가 뒤 코드가 주석 처리됨(`teal3.mjs`) — 이미 이 날 한 번 겪은 실수를 테스트 파일에서 반복. `node --check` 로 즉시 발견.
- **플레이테스트 러너가 크래시했는데 원인이 가려졌다**: 스크래치 디렉터리의 테스트 복사본이 옛것이었고 `CHROME_EXE` 도 안 넘겼는데, 크래시 핸들러가 아직 선언 안 된 `logs` 를 참조해 `Cannot access 'logs' before initialization` 만 찍혔다.

## 왜 어긋났나
1. **전투 UI 의 기준은 델타룬 실물인데, 구성은 내 것이었다.** 카드형 HP·별도 문구 상태·카드 안 버튼은 전부 브리핑에 없는 내 구성이고, 사용자는 델타룬 화면(문구 상자 + 버튼 줄 + 하단 HP 띠)을 머리에 두고 본다. **이전 포스트모텀 1번("느낌 값은 델타룬 기준")과 같은 실수**를 UI 구성에서 반복했다.
2. **"공식 사운드" 를 파일명으로 해석했다.** 사용자는 '들어서 아는 소리' 기준이다. 이미 사용자가 고른 사운드(진입 징글)를 내 판단으로 교체한 것, 리포에 있는 이름(`snd_won`)을 검증 없이 "그 소리" 로 단정한 것 — 두 번 지적받았다.
3. **튜토리얼 전용 흐름을 표준 흐름에 복사했다.** `{bgm:null}` 은 "동료 합류 뒤 브금 끔" 같은 컷신 지시에서 온 것인데, 조우 표준 스크립트에 그대로 들어갔다. 표준 흐름을 만들 땐 "이 줄이 왜 있지?" 를 줄마다 물어야 했다.
4. **검사가 프록시만 봤다.** 동상 검사는 `hopY > 10` 만 봐서 "위로 뛰었다" 는 잡았지만 "옆으로 안 갔다" 는 못 잡았고, 스크린샷은 발사 직후 프레임이라 제자리 점프도 그럴듯해 보였다. 렌더 경로(`drawX` 가 `def.ix` 를 따름)를 안 읽고 엔티티 좌표만 바꿨다.
5. **데이터 문구가 다른 엔티티 상태를 참조했다.** 잡담은 "살아 있는 적 하나에서 무작위" 라는 실행 규칙을 데이터 작성 때 잊었다.
6. **원문 복사 규칙에 오타 검토가 없었다.** "대사 그대로" 는 맞지만, 의심 오타는 요약에 한 줄로 표시해 사용자가 결정하게 했어야 한다.
7. **큰 패치를 문자열 슬라이스로 했다.** 앵커 순서를 확인하지 않는 슬라이스는 문법이 멀쩡한 채로 파일을 망가뜨린다.

## 잘된 것
- 전투가 **상태 기계 + 데이터(enemies/items)** 라 UI 재배치·문구 위치 이동·아이템 분류 변경이 그리기 함수 두 개와 데이터 파일로 끝났다.
- `{fling}` 을 새 노드로 두고 `{hop}` 도 같이 고쳐서 이후 "소품 날리기" 는 한 줄이다.
- 플레이테스트가 있어서 y 재배치·오타 수정이 기대값 실패로 바로 드러났고, 브금 복귀·잡담 공존은 체크로 고정했다.
- 승리음은 두 파일의 피치 윤곽을 비교해 "실제로 다른 소리" 임을 확인하고 바꿨다(감으로 바꾸지 않음).

## 앞으로 지킬 것 (STATE.md "확정 규칙" 에 반영)
- **전투 UI 는 델타룬 화면 구성을 기본값으로**: 문구 상자(행동 고르는 동안 잡담 유지) + 버튼 줄 + 하단 HP 띠. 새 요소는 "델타룬에선 어디 있나" 부터.
- **사용자가 고른 오디오는 교체 금지.** "공식으로" 지시는 아직 안 고른 소리에만 적용하고, 후보가 둘이면 둘 다 넣고 어느 걸 적용했는지 요약에 쓴다. 언더테일/델타룬 이름이 다른 소리(`snd_won` vs `snd_victor`)는 references.md 에 병기.
- **표준 흐름(조우·맵 이동)은 컷신에서 복사하지 않는다.** 만들 때 줄마다 "일반 맵에서도 맞나" 를 묻고, 튜토리얼 예외는 컷신 쪽에 둔다.
- **연출 검사는 눈에 보이는 값으로**: 소품은 `drawX/drawY(+flyX/flyY)`, 캐릭터는 `x/y` — 그리고 스크린샷은 연출 **중간** 프레임.
- **적 잡담·나레이션 데이터는 단독 문장.** 다른 엔티티·복수 전제 금지(단위 테스트).
- **아이템은 획득 스크립트를 쓰는 순간 레지스트리에 kind·desc 등록**(단위 테스트가 미등록을 막음).
- **원문 복사 시 의심 오타는 요약에 표시.**
- **패치 도구 규칙**: 슬라이스 교체는 `assert a < b`, 끝나면 메서드 이름 중복 grep; 한 줄 문장 끝에 `//` 주석 금지(테스트 파일 포함); `node --check` 는 전 파일.
- **플레이테스트는 `tests/playtest/run.sh`** 로(복사본·`CHROME_EXE`·`SHOT_DIR` 자동), 크래시 핸들러는 진짜 에러를 보여 준다.
