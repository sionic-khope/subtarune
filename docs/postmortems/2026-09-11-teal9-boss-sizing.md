# 포스트모텀 — 청록숲9 레드·블루 크기·배치 (2026-09-11)

## 무슨 일이 있었나
1. 사용자: "레드랑 블루 좀 훨씬 커야 해, 지금보다 두 배" → 필드 2.6배(238px)·전투 2.0배(192px)로 올렸다.
2. 스크린샷을 보고도 커밋했다. 이벤트 카메라에서 **레드 머리가 화면 위로 잘리고**, 블루가 파티(빠맨)와 레드를 **덮었다**. 전투에서는 레드가 **화면 오른쪽·위로 잘리고** 블루 하반신이 **패널 뒤로** 들어갔다.
3. 사용자: "지금은 너무 크고 배열이 이상하잖아", "너무 커서 잘리기도 함 이벤트일 때", "인게임 전투도 마찬가지고".

## 원인
- **크기를 '배수'로만 결정하고 화면 제약을 계산하지 않았다.** 이벤트 카메라는 480×360 에서 대화창(아래 130px)을 빼면 **230px** 만 보인다. 전투는 480×360 에서 패널(y 246~)을 빼면 **246px**. 238px 그림 둘을 세로로 세우면 어떤 카메라로도 다 보일 수 없다.
- **배치를 겹침 계산 없이 '엇갈리게'로 얼버무렸다.** 위·아래 엇갈림은 큰 그림에선 그냥 덮는 것이 된다. 파티 열과의 가로 간격도 재지 않았다.
- **스크린샷을 '있는지'만 보고 '잘렸는지'를 안 봤다.** 전투 스샷에서 레드가 오른쪽 가장자리에 걸린 게 보였는데 넘어갔다.
- 테스트가 크기 하한(≥ 3배)만 재고 **상한·화면 안·겹침**을 재지 않아서, 과한 값이 통과했다.

## 고친 것
- 필드 1.8배(165px, 형섭의 2.2배), 전투 1.5배(144px). 둘은 문 앞 **같은 열**에 위·아래로(그림 51~216 / 219~384) 안 겹친다. 파티는 광장 왼쪽 길(42열)에 세로 정렬 — 블루 그림(x 1542~)과 150px 떨어짐. **카메라는 말하는 쪽으로**(델타룬): 레드·파티 대사는 `CAM_RED`(레드 전신 + 파티), 블루 대사는 `CAM_BLUE`(블루 전신), 응수는 가운데 — 165px 둘을 230px 창에 동시에 넣을 수 없으니 화자별로 보여 준다.
- 전투: 레드 발 y 144(위 0), 블루 발 y 246(패널 윗선), 가로 40px 엇갈림 → 화면 안·패널 위.
- **수치 검사 추가**: `tests/playtest/teal9.mjs` 가 정렬 순간 카메라 사각형·레드/블루/파티 그림 사각형을 재서 "레드 전신 보임·블루 윗부분 보임·서로/파티와 안 겹침" 을 검사. `tests/playtest/enemy.mjs` 가 모든 적의 그림 사각형이 480×360 안·y ≤ 250 인지 검사(모든 적에 적용).
- 전투 배경 레지스트리(`src/battle/backgrounds.js`, `temple` 무대) — 보스전을 색다르게 하려는 요청과 함께.

## 규칙 (스킬에 반영)
- **큰 캐릭터는 배수가 아니라 보이는 영역으로 정한다**: 이벤트 = 카메라 높이 − 대화창 = 230px, 전투 = 패널 윗선 246px. 둘을 세로로 세우면 각 ≤ 그 절반.
- **배치는 사각형으로 계산**해 "안 겹침·안 잘림" 을 테스트에 넣고 나서 스크린샷을 본다. 스크린샷은 가장자리 4곳에 걸린 그림이 없는지 본다.
- 사용자의 "두 배" 같은 배수 지시는 **"보이는 크기가 지금보다 확실히 크게"** 로 읽고, 화면 제약 안에서 최대치를 잡은 뒤 수치와 스샷으로 보고한다.
