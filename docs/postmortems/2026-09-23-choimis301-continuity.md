# 최미스 승리·귀환 연속성 교정

2026-09-23 · BUILD300 후속 피드백 → BUILD301 로컬 수정. 최종 통합 QA·메인·배포는 진행 중이며 이 문서는 완료 승인서가 아니다.

## 사용자가 겪은 문제와 원인

| 증상 | 확인한 원인 |301 수정의 소유 경로 |
| --- | --- | --- |
| 승리 뒤 대사는 진행되지만 검은 화면이 남음 | 공통 승리 종료가 남긴 `fade.alpha=1`을 구조 첫 대사 전에 해제하지 않았다. 구조 장면만 직접 시작한 fixture는 이미 페이드가0이라 이 경계를 지나지 않았다. | `src/data/cutscenes/choimis_rescue.js`의 첫 대사 전0.65초 `fade:'in'` |
| 얼굴이 없는 인물에게 엉뚱한 기본 얼굴 표시 | `Game.makePortraits()`가 실제 자산 적재 전에도 공통 몸체/팔레트로 얼굴을 만들었고, 파크 대사는 실제 의상 배우와 다른 키를 요청했다. | `src/main.js`의 실자산 초상화 구성, `src/ui/dialogue.js`의 없는 얼굴 처리, `ship_lounge.js`의 `park_guardian_costume` |
| 쥰희의 자랑을 끊는 박자가 늦음 | 기존 `cut:2.1`이 요청한 중간 끼어들기보다 늦었다. `cut` 노드가 있다는 사실만 확인하고 그 순간 실제로 얼마나 타이핑됐는지는 충분히 확인하지 않았다. | `ship_lounge_briefing.js`의 자랑 줄 `cut:1.05` |
| 상점 강화품이 회복품이 됨 | 표시 이름의 “더 강한”만 보고 기존 상품의 실제 `stat`/`onceFlag` 의미를 대조하지 않았다. | `src/data/shops.js`의 새 영구 강화 단계, `src/data/items.js`의 별도 음식·과거 이름 정규화 |
| 요청한 상승음·큰 타격음의 연결을 혼동할 위험 | 내부 파일명이나 음원 제목만으로 장면 역할·원음을 추정하면 `wing`, `spearappear`, `furnace_blast`를 잘못 고를 수 있다. | 실제 비데/청소부 큐와 원음 보존 기록을 대조한 [301 오디오 기록](../../design/audio/references.md) |

승리 경계의 재현에서는 원래 절벽 트리거→같은 스크립트의 전투 진입 뒤 공개한 전투 완료 fixture를 쓰고, 실제 C 입력으로 승리창을 닫았다. 수정 전 `battle=false`, 구조 자산 준비 완료, 첫 대사 `휴 드디어 잡았네요`, 오류 없음인데도 검정 페이드가1이었다. 수정 후 같은 경계에서 페이드0을 확인했다. 이는 자연 전투 공략 완주 증거가 아니며, 이전의 구조 장면 단독 PASS를 승리 경계 검증으로 확대하지 않는다. 보존 시나리오는 [choimis-win-rescue](../../tests/playtest/choimis-win-rescue.mjs)다.

## 이번 변경의 경계

냄트기의 밤바다·한 번 통과/세 명 동시 포획은 새 연출 요청이다. 검정 페이드 원인과 분리해 구현했으며, `catchCount`가3이라는 결과만으로 세 번의 비행을 정당화하지 않는다. 실제 접촉 전/접촉 순간/통과 뒤의 제트기·세 인물 위치를 함께 본다.

얼굴이 없으면 화자·음성과 본문은 유지하고 얼굴 칸만 비운다. 이미 적재된 전용 초상화는 재구성 때 보존하고, 시트에서 추출할 때는 요청한 캐릭터의 실제 전면 프레임을 쓴다. 일반 필드 스프라이트의 로딩 폴백 정책을 이 변경에 섞지 않는다.

상점의 현재 계약은 씨알리스 공격력+1, 바세린 최대HP+20이다. 구조 후 새 단계는 기존 단계와 별도1회 구매 플래그를 갖는다. 음식은 핫도그 한 명150/기름떡볶이 일행100회복이다. 과거 저장의 잘못된 회복품 이름만 수량·순서 그대로 바꾸며, 이름 정규화로 돈·능력치·구매 플래그를 다시 적용하지 않는다.

## 다음 검수에서 확인할 순서

1. 호출 대상의 실제 데이터/자산 키→소비자→화면과 효과를 연결한다. 상품명·파일명·초상화 키의 유사성을 기능의 증거로 삼지 않는다.
2. 이전 장면이 남기는 페이드·카메라·음악·입력을 기록한 뒤 다음 장면의 첫 대사까지 실제 경계를 지난다. fixture가 생략한 경계는 미검증으로 남긴다.
3. 말 끊김은 표시 중간·끊기는 순간·다음 화자에서 확인한다. 완독 후 `auto`와 타이핑 중 `cut`을 구별한다.
4. 승리 보상·상점 구매·아이템 사용은 전후 돈/수량/능력치와 재시도·재입장·저장 복원에서 한 번만 적용되는지 확인한다.
5. 수치 검사, 실제 캡처/청취, 독립 검수, 메인 반영·배포를 따로 보고한다. 분야별 녹색 테스트를 최종 사용자 화면의 승인으로 대신하지 않는다.

관련 회귀는 `choimis-finale-flow`, `choimis-rescue`, `ship-lounge-briefing`, `dialogue-portraits`, `shop301`, `item-use` 단위 검사와 승리→구조→라운지 재사용 플레이테스트다. 최신 요구 전체의 최종 판정은 [STATE](../STATE.md)의301 완료 기록에서 확정한다.
