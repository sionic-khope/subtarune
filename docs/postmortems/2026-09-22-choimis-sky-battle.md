# 최미스 공중 전투: 장면 연결과 조작의 실제 기준

BUILD294 구현 도중 사용자가 실제8895 화면을 보고 꽃잎 발판 소실, 과한 최미스 크기, 보이지 않는 바다, 이른 후렴을 지적했다. 코드 연결과 화면 만족은 별도였으며 아래 사항을 수정했다.

## 다시 작업할 때 확인할 순서

1. 상승 마지막 프레임과 전투 첫 프레임을 나란히 본다. 네 배우의 발 기준점·불투명 몸 높이·꽃잎 받침·원경이 이어져야 한다. 원본 시트 셀 크기나 배율만 같다고 연속성을 승인하지 않는다.
2. 메뉴→공격→적 턴을 실제 입력으로 지난다. 배경/꽃잎은 연속 시계를 쓰며 상태 타이머 초기화로 제자리로 튀지 않아야 한다. 선공의 오른쪽 분홍 하트는 실제 도트 끝 방향과 C 총알 진행 방향을 함께 확인한다.
3. 음악이 재생되는 동안 지정 구간과 반복 구간을 본다. 자동 온셋은 악기 어택 후보이지 보컬 음절 정답이 아니므로 사용자 청취 피드백을 타임스탬프에 반영한다. 마지막 글자도 다음 cue 전에 실제 색이 채워져 보여야 한다.
4. 상승/꽃잎 모으기/상승 이동 도중 타이틀·맵을 바꾼다. 장면 소유 콜백과 대기는 끝나고 새 카메라/배우를 다시 움직이지 않아야 한다. 공유 background 목록 전체를 지우는 대신 소유한 작업만 취소한다.

## 원인과 교정

- 처음에는 전투용 배경만 갈아 끼워 상승에서 발밑을 받치던 꽃잎이 사라졌다. 전투 렌더도 배우의 현재 발 위치를 따라 받침을 그리며, 흩날리는 꽃잎과 지지용 밀집 꽃잎을 구분했다.
- 최미스160px 셀을 기존 렌더 배수로 그려 동료보다 과하게 컸다. 실제 불투명 몸 높이를 기준으로 맞추고 손 올린 포즈의 높이는 별도로 보정했다. 사용자 수정은 렌더 크기이며 승인된 얼굴·망토 원본을 다시 그리지 않았다.
- 하늘만 잘라 쓴 배경의 끝에 수평선 한 줄이 남고 아래는 단색이었다. 최신 사용자 지시에 따라 아래 밤바다를 복구하고 원경과 근경 받침을 분리했다.
- 후렴 첫 글자 하나만 지연하면 다음 글자와 동시에 채워진다. 두 호출 구절의 음절 순서를 함께 옮기되 BGM이나 다른 절의 시작은 바꾸지 않았다.
- 사격 하트의 메타데이터는 right였지만 실제 픽셀의 끝은 왼쪽이었다. 도트의 단일 꼭짓점 위치를 검사하고 변신 전 빨간 하트는 아래, 변신 후 분홍 하트는 오른쪽으로 그린다.
- 취소 시 화면 효과만 지워서는 대기 Promise와 배경 콜백이 남았다. 장면 토큰·소유 대기를 취소하고 오래된 후속 콜백이 새 장면을 건드리지 않는 회귀 검사를 추가했다.
- 넓어진 선공 창이 형섭의 몸을 가려 머리만 남기는 구도는 기믹 자체가 동작해도 화면 검수에서 실패다. 창이 움직이기 전에 배우와 받침을 함께 짧게 숨기고 사격 종료 후 함께 복구한다. 하늘·바다·자막·HP는 유지하며 전환 전후를 따로 확인한다.
- 생성한 의상에 별도의 사각 클립과 흰 무늬를 덧씌우면 승인된 옷이 막대처럼 보인다. 패션 탄은 원본 프레임의 불투명 경계만 잘라 비율대로 그리며 같은 알파 마스크로 충돌을 검사한다. 예고선과 실제 옷 그림을 분리하고 투명한 소매 사이에도 피해를 주지 않는다.
- 꽃잎 224개가 살아 있어도 절벽 바닥 소품보다 먼저 그리면 모이는 모습이 전부 가려진다. 바닥 소품 이후, 받침을 쓰는 첫 배우 직전에 꽃잎을 한 번 그린다. 입자 수 검사와 별도로 상승 전 실제 발밑에 분홍 꽃잎이 보이는 프레임을 확인한다.
- 절벽 아래에서 올라온다는 말을 착지로 해석하지 않는다. 최미스는 등장 뒤에도 계속 떠 있어야 한다. 대사와 손짓 중의 공중 간격, 일행 상승 시작 시 실제 발 위치의 연속성까지 확인한다.

## 검증을 혼동하지 않기

QA 시작점은 스토리 준비 fixture이며 자연 스토리 완주가 아니다. 캡처 지연으로 중간 위상을 놓친 실패, 잘못된 HP 저장소를 읽은 실패, 검증 도중 소스를 바꾼 실패는 각각 고친 뒤 새 실행으로 판단한다. 과거 실패 캡처는 최종 승인 근거로 재사용하지 않는다. 음원 디코드·시계 동기화와 사람이 들은 박자 만족도도 따로 기록한다.

다음 장면 연결이나 음악 패턴을 고칠 때는 먼저 기존 `choimis-sky-battle` 재사용 시나리오와 최신 검증 기록을 열어 해당 경계부터 재생한다.

## BUILD295 후속 교정

- 타깃 기믹은 마지막 명중 직후 같은 update에서 dispose될 수 있다. 80ms 외부 폴링만으로 마지막 명중을 읽으면 성공한 전투도 실패로 기록한다. 실제 update가 남긴 스냅샷을 관찰용으로 보관하고 종료 뒤 검증하되 명중·체력·성공 상태를 주입하지 않는다. 이동 조준과 방패 회전의 탄속 계산은 전체/부분 QA가 같은 입력 함수를 사용한다.
- 도구에 표시된 PNG에서 글자·캐릭터가 비어 보이더라도 실제 파일의 해당 영역을 디코딩해 확인한다. 이번에는 사라져 보인 안내와 정상 안내의 RGB 해시가 동일했다. 도구 이미지 표시 문제를 게임 렌더 결함으로 단정해 정상 소스를 바꾸지 않는다.

- 떠 있다는 표현을 반복 바운스로 고정하지 않는다. 사용자는 최미스가 동동 튀는 움직임을 거부했으므로 등장 후와 전투 대기는 좌표를 고정하고 망토만 움직인다. 상승 연출과 대기 동작은 별도 설정으로 관리한다.

- 공중 간격만 띄워도 발 아래 절벽이 남으면 땅 위에 떠 있는 것으로 읽힌다. 보스 발은 절벽 끝보다 오른쪽 허공에 두고, 일행은 충돌 가능한 바닥 안에서 앞쪽으로 이동한다. 2초 카메라 선행→상승→대사 순서를 실제 전체 화면으로 확인한다.
- 최신 지지물 지시는 일행 셋만 꽃잎으로 받치는 것이다. 위 BUILD294의 네 배우 받침 설명보다 우선한다. 보스는 망토를 뒤로 쥐고 한쪽 무릎을 든 자세로 스스로 떠 있다.
- C를 단발 직후 다시 누른 채 유지하면 쿨다운 중의 첫 눌림을 버려 충전이 영원히 시작되지 않았다. 눌림 엣지만 보지 않고 쿨다운이 끝났을 때 유지 중인 입력을 받아들이되 최초 진입 때 이미 누른 C는 계속 차단한다. 이 입력 순서를 회귀 검사로 고정한다.
- 이동하는 천혈 표적을 현재 좌표로만 조준하는 QA는 총알의 약0.7초 비행을 무시한다. 명중 수를 주입하거나 성공 조건을 줄이지 말고 실제 입력 조준을 보완한다. 여섯 번째 명중 후 빔 소멸과 메뉴 복귀를 별도로 확인한다.
- 최종 프레임 하나로 차징·망토·강화 연출을 승인하지 않는다. 충전 중간/최대/놓기, 꽃 모임 중간/절정, 망토 네 위상과 바다 이동을 연속 캡처한다. 누락된 캡처와 실제 렌더 결함은 원인을 확인하기 전까지 구분해 기록한다.
- 재사용 플레이테스트는 `tests/playtest/run.sh`의 캐시 런타임으로 실행한다. 프로젝트 루트에 임의의 package.json을 만들면 ES 모듈 해석이 바뀐다. 이번 검증 중 생긴 해당 임시 파일은 제거했고, 의존성 설치 없이 기존 런너를 사용한다.
