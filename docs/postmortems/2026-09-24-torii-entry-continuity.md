# 보라 토리이의 첫 진입과 연속성

## 사용자에게 보인 문제

갈림길 입장 중 주인공들이 보이기 전에 느낌표가 나왔고, 마리오가 기존 전용음 대신 공용 점프음을 냈다. 북쪽 구멍은 벽 없이 네모로 떠 보였으며 진행하면 막히지 않았다. 토리이는 자연 진행에서 자동 질주가 시작되지 않았고 전투 준비 중 화면도 끊겼다.

## 원인과 놓친 검사

- `early:true`가 지도 페이드 안에서 반응을 시작했다. 이전 QA는 페이드 후 느낌표가 존재하는지만 보고 반응 시작 시각을 비교하지 않았다.
- 전용 `mario_jump`가 다른 마리오 장면에 이미 있는데도 일반 `jump`를 넣었다.
- 토리이 트리거의 `requires:castle_malzahar_split`는 지도 생성 때 제거 조건이었다. 같은 맵의 대화가 해당 플래그를 켜도 사라진 트리거가 다시 생기지 않았다. 이전 검사는 토리이 앞에서 멈춰 `!runner`를 승인했다.
- 전투의 비동기 로딩 동안 일반 루프는 필드 runner 갱신/그리기를 중단했지만 seamless 전투는 아직 그릴 화면이 없었다. 로딩 시작 때 저장한 자세도 실제 인계 순간에는 오래된 상태였다.
- 구멍은 큰 사각형으로 문틀까지 덮었고, 북쪽 방어선은 서 있는 배우만 있을 뿐 통행 차단이 없었다.

## 수정과 완료 기준

파란 토리이의 기존 자동 시작 스크립트와 준비/달리기를 재사용한다. 트리거는 첫 입장부터 존재하며 실제 기둥 사이에 둔다. QA 스폰도 입장 쿨다운이 끝나기 전에 트리거를 지나쳐버리지 않도록 문턱보다 충분히 앞에 둔다.

전투가 로딩 중이어도 같은 runner를 계속 갱신·렌더하고, 준비가 끝나는 순간 자세/카메라를 넘긴다. 느린 로딩에서 길 끝에 닿아 멈추는 경우도 검사한다. 시각적 전환은 하트/음영/HUD의 점진적 공개이며 검은 빈 프레임이 아니다.

입장 fade=0 → 세 사람 노출0.65초 → 느낌표 순서, Mario 전용 파일의 실제 재생, 벽에 붙은 아치의 중간 화면, 북쪽/승리 후 왼쪽으로 계속 걷는 실제 차단, 방향키만으로 준비→달리기→전투 진입을 각각 검증한다. 자연 첫 방문, QA 바로가기, 저장 재진입은 서로 대체하지 않는다. 결과와 최종 소스는 `.omc/evidence/entry312/ledger.md`에 기록한다.
