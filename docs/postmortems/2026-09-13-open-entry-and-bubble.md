# 열린 선체 입구와 기존 말풍선 재사용 실패

2026-09-13 · BUILD139 사용자 반려 → BUILD140 수정

## 사용자가 겪은 문제

- ‘뚫려있는 디자인인데 c를 누르면 전함으로 이동되는게 말이되냐’: 철다리 끝 열린 선체 입구에서 걸어 들어가도 멈추고 C를 눌러야 했다.
- ‘... 말풍선 연출 이미 있는거 있는데 왜 새로만든거야’: 쥰희·경섭의 반응을 기존 말풍선 대신 흰 글자 도장으로 표시했다.
- 쥰희가 문 앞에서 사라져 실제 문을 지나갔다는 느낌이 없고 용준의 뒤따라 입장도 불분명했다.

## 원인

구현과 완료 판단을 맡은 Codex의 실패다.

1. ‘그림이 있는 문은 C’라는 과도한 지침을 실제로 열린 통로에도 적용했다. 그림의 문짝/빈 공간을 확인하지 않았다.
2. 검증 때 잘못 정한 C 입력을 전제로 삼았다. 우측 C 판정을 더 넓히고 테스트를 통과시켜 잘못된 상호작용을 강화했다. 테스트 개수와 리뷰 승인은 사용자 의도 일치의 증거가 아니었다.
3. `bubble` 명령과 `src/ui/bubble.js`가 이미 있는데 `stamp`로 점 글자를 만들었다. 재사용할 기능을 확인하기 전에 표면상 비슷한 출력을 만들었다.
4. NPC가 문 앞 좌표에 도착한 뒤 제거되는 것을 입장 완료로 취급했다. 발 방향·문턱 통과·문틀 가림·소리 시점의 중간 화면을 보지 않았다.

## 교정과 재발 방지

- 열린 선체 입구는 기존 Door의 자동 겹침 전환을 사용하고 불필요한 철컥 소리를 제거한다. 선체 벽 충돌과 그림은 유지한다.
- 기존 C 프로브 검사를 실제 Door.update의 방향키 통과 계약으로 교체했다. 수정 전 실패, 수정 후 문턱 직전 미발동/진입 발동/귀환 스폰 재전환 없음으로 통과한다.
- 기존 DotBubble의 동일한 모양과 점 타이밍을 재사용한다. 여러 대상은 공용 시계와 대상 배열로 확장해 둘 중 하나만 덮어쓰는 문제를 막는다.
- 닫힌 내부 문 퇴장은 문 열림·철컥·쥰희 문 안쪽 이동/가림→용준 후행으로 확인한다. 문 앞에서 즉시 제거하는 것을 성공으로 취급하지 않는다.
- 입력 판정은 map 스킬 ‘출입구 조작 판정’, 말풍선은 cutscene 스킬 `bubble` 항목 한 곳에 관리한다. 이 문서는 실패 이유와 관찰을 보존한다.

## 검증 범위

철다리 방향키 통과, 기존 두 말풍선, TV 장면 교체, 내부 문 두 NPC 입장과 조작 복귀만 실제로 확인한다. 관계없는 게임 전체나 반복 리뷰로 대신하지 않는다. 최종 실행 증거·배포 빌드는 `docs/STATE.md`의 BUILD140 기록을 따른다.
