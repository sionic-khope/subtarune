# 코딩 담당 → 선택한 이미지 제작 담당

먼저 [공통 제작 스킬](../../subtarune-sprite-production/SKILL.md)을 읽고 제작 경로를 정한다. 아래 요청/회수 계약은 Fable·Claude·Codex에 공통이다. Codex queue 부분은 **기존 Codex 작업에 맡길 때만** 사용하며 이미지 API 경로의 필수 설치 절차가 아니다.

## 요청 준비

1. 기존 승인 자산을 찾은 뒤 실제로 새 이미지/외형 편집이 필요한 경우에만 요청한다. 같은 요청에 작업 ID 하나를 부여하고, 개발 worktree의 `.omc/handoffs/sprites/<작업ID>/request.md`에 명세를 쓴다. 다른 worktree에서 읽을 수 있게 절대 경로도 기록한다.
2. 명세에는 사용자 원문, 개발 저장소·브랜치·기준 커밋, 참고 이미지 절대 경로, 보존 외형, 필요한 동작·방향·프레임/피벗/배율, 사용 화면, 출력 디렉터리, 결과 파일 경로를 넣는다. 출력은 해당 요청의 `delivery/`로 제한하고 개발자가 수정 중인 runtime 파일은 생성 담당이 바꾸지 않게 한다.
3. `result.json`의 계약을 정한다: `requestId`, `status`, `files`(절대 경로), `contract`(프레임/피벗 등 문서 경로), `notes`. 생성 담당은 `working` 후 실제 생성·후처리·검수까지 끝났을 때만 `ready`를 기록한다. 실패/생성 도구 미지원은 `blocked`와 이유를 기록한다. 요청자는 준비 상태를 `requested`, 통합 완료를 `integrated`로 관리한다. 기존 결과는 같은 작업 ID인지 확인한다.

## 이미지 API로 제작할 때

[공급자 확인](../../subtarune-sprite-production/references/providers.md) 후 실제 실행 가능한 API 도구/스크립트에 같은 요청을 전달한다. OpenGateway는 `tools/sprites/imagegen.py`와 [subtarune-imagegen](../../subtarune-imagegen/SKILL.md)이 그 실행기다(2026-09-14 사용자 확정, 키가 있으면 기본 경로). 모델 ID·참조 파일·설정·과금 단위/상한은 요청별로 기록하고 비밀키는 결과/프롬프트에서 제외한다. 이 문서는 OG/OpenAI/Gemini 호출 스크립트를 새로 설치하거나 실행한 상태를 뜻하지 않는다. API 실행기 또는 필요한 참고 이미지 기능이 없으면 명세와 구체 부족 항목을 반환한다.

호출 성공 뒤 raw만 있으면 `working`이다. 최종 시트 디코드·프레임·피벗·투명도·동작 검수가 끝나야 `ready`이며, 엔진 등록/실제 장면 확인 뒤에만 코딩 담당이 `integrated`로 올린다. 실패한 참고 이미지 업로드를 생략하고 text-only로 재시도하거나 다른 유료 모델로 자동 전환하지 않는다.

## 이 컴퓨터의 연결된 제작 담당

`git rev-parse --git-common-dir`로 얻은 공통 Git 디렉터리 안의 `codex-sprite-target.json`을 읽는다. 이 파일은 이 컴퓨터의 작업 ID/경로를 담는 로컬 설정이며 저장소에 커밋하지 않는다. worktree도 같은 설정을 공유한다. 현재 대화에 연결한 로컬 설정은 이미 존재하는 Codex 제작 작업을 대상으로 한다.

`codex queue --help`로 현재 CLI가 `--thread`/`--message`를 지원하는지 확인한다. 설정의 `threadId`와 명세의 절대 경로를 사용해 해당 기존 작업에 한 번 요청한다. 아래 변수는 설정/명세에서 안전하게 읽은 문자열이며 미리 실제 값으로 설정해야 한다.

```sh
codex queue --thread "$SPRITE_THREAD_ID" --message "$SPRITE_MESSAGE"
```

메시지 내용: “스프라이트 제작 요청 <작업ID>. <request.md 절대 경로>를 읽고 해당 생성 스킬/내장 이미지 생성 도구로 제작한다. 결과는 지정 delivery와 result.json에 기록한다. runtime 코드·커밋·머지는 개발 담당이 소유한다.” 참고 이미지가 필요하면 CLI가 지원하는 `--image`에 각 실제 경로를 붙인다. 자유 텍스트를 셸 코드나 명령 치환으로 평가하지 않는다.

작업 ID·명세 경로·전송 성공 여부를 기록한다. 전송 성공은 **접수**이지 제작 완료가 아니다. 같은 요청을 재전송하기 전에 result와 앞선 접수 기록을 확인한다. 임의의 최근 작업(`--last`)을 선택하거나 별도 생성 작업을 무조건 새로 만들지 않는다. 대상 작업의 모델/이미지 생성 설정은 유지한다.

연결 파일이나 CLI가 없거나 대상이 유효하지 않으면, 명세를 그대로 Codex에 전달할 수 있게 사용자에게 경로와 짧은 요청문을 제공한다. 기존 자산으로 가능한 코딩은 계속한다. CLI 존재만으로 새 `codex exec` 세션에 앱의 내장 이미지 도구가 있다고 가정하지 않는다. 다른 유료 이미지 API나 생성 모델로 자동 전환하지 않는다.

## 제작과 회수

Codex는 명세와 원본을 읽고 실제 생성 도구가 사용 가능한지 확인한다. 외형 생성/편집은 이미지 도구와 해당 제작 스킬로 수행한다. 기계적 후처리는 같은 피벗·공통 배율·알파 기준을 지킨다. 원본/프롬프트/후처리/QC를 결과에 포함하고, 자신의 작업 밖 코드나 다른 요청의 파일을 덮어쓰지 않는다.

코딩 담당은 기다리는 동안 자산과 독립적인 코드 작업을 진행한다. `ready`를 받은 뒤 PNG 존재·디코드·프레임 수·규격과 실제 이미지를 확인하고 요청 ID/명세와 대조한다. 불일치는 구체적인 수정 항목으로 같은 제작 요청에 돌려준다. 완료된 자산을 게임의 `assets/source/`와 runtime 경로에 통합한 다음 preload·레지스트리·모션·실제 장면을 검증한다. 브랜치가 달라졌다면 원본 기준과 현재 사용처를 재대조한다.

이미지 제작 담당은 자산을, 코딩 담당은 코드와 최종 게임 통합·승인된 머지를 소유한다. `ready` 파일만으로 게임까지 완료됐다고 보고하지 않는다.

## 확인된 범위

2026-09-14 이 컴퓨터에서 기존 작업에 메시지를 보내는 명령 형식은 설치된 `codex queue --help`로 확인했다. 이 지침 갱신에서는 실제 전송이나 새 이미지 요청, Claude→Codex→통합 전체 실행을 시험하지 않았다. 최초 실제 제작 요청 때 접수·생성 도구 실행·산출물·게임 표시까지 기록한다. 일반 CLI 자동 실행은 [공식 비대화형 실행 문서](https://learn.chatgpt.com/docs/non-interactive-mode)에 설명돼 있지만, 별도 세션의 이미지 생성 도구 가용성을 보장하는 근거로 사용하지 않는다.
