# 스프라이트 제작과 코딩의 전달 계약

사용자 최신 선호(2026-09-14): Fable/Claude 등 다른 모델이 코딩하고 이미지 생성 모델을 교체해도 승인된 스프라이트 품질과 연출을 유지한다. 연결된 Codex 제작 담당과 사용자가 선택한 이미지 API는 대체 가능한 제작 경로이며, 이 요청만으로 외부 유료 호출을 실행하지 않는다.

새 그림/외형 편집은 [공통 제작 스킬](../subtarune-sprite-production/SKILL.md)의 결과 계약을 정한 뒤 [요청·회수 절차](references/dispatch.md)의 선택한 제작 경로로 보낸다. 코딩 담당은 명세·엔진 등록·배치·테스트를 맡는다. 실제 이미지 도구/API 실행 능력이 있는 같은 에이전트가 제작을 겸할 수 있지만, 기존 파일 복사·시트 분할과 새로운 외형 생성은 구분한다.

## 코드 작성자가 먼저 할 일

1. 기존 `assets/source/`, `assets/sprites/`, `assets/enemies/`, `docs/handoffs/`에서 승인 자산과 사용처를 찾는다. 이미 만든 관중/인사 시트가 안 보이면 경로·preload·레지스트리·프레임·hidden·레이어·카메라를 먼저 조사한다. 파일을 다시 생성하는 것은 연결 실패의 해결책이 아니다.
2. 새 그림이 필요하면 제작 요청에 캐릭터/참조 원본, 쓰일 화면과 동작, 방향, 셀 크기·행열·프레임 순서/시간, 투명 배경, 발/무기 피벗, 목표 화면 크기, 보존할 외형, 출력 경로를 적는다. 기존 자산의 규격이 우선이며 보스를 모두64px로 정규화하지 않는다.
3. 요청서에 선택한 제작 담당/공급자와 출력 소유권을 적는다. 실제 도구·참조 지원·비용 경계를 확인하고 공통 제작 스킬로 전달한다. 담당/도구가 없으면 기존 자산으로 가능한 코드 작업을 진행하고, 제작 요청서를 전달 가능한 상태로 남긴다. 생성 능력이 있다고 가장하거나 코드로 캐릭터 도트를 임의 재디자인하지 않는다.

## 제작 결과에 필요한 것

최종 PNG/시트, 원본과 실제 프롬프트, 프레임 순서·duration·pivot·공통 scale, 투명도/색키·최근접 처리, 방향별 또는 동작 미리보기, 알려진 한계를 해당 `assets/source/<작업>/` 계약에 둔다. 기존 원본과 반려 초안을 최종 자산과 구별한다. 재현 스크립트는 실제 입력 경로와 결과를 갖는다.

## 통합자가 검증할 것

등록 흐름은 `src/data/characters.js`, `character-motions.js`, `src/world/character-motion.js`, 해당 맵 preload, 전투 enemy/sheet/pivot 사용처를 따라간다. 기존 클래스 이름만 보고 사람형 폴백을 허용하지 않는다.

프레임을 바꿀 때 발 고정, 몸통·머리 비율, 손/무기의 접점, 방향별 정체성, 시트 경계, 알파 가장자리, 근접/전체 구도에서의 화면 크기를 확인한다. 시트 자체의 움직임 위에 임의 sway/회전/늘이기를 겹치지 않는다. 그림 rect와 충돌/조사 rect는 역할별로 분리한다.

### 재생·전환 계약

생성 프롬프트의 포즈 순서는 실행 코드가 아니다. 전달받은 행/열·인덱스 기준·방향/행동별 셀과 재생 순서·duration·loop/one-shot·피벗을 실제 로더에 대응시킨다. [world.js](../../../src/world/world.js)의 일반 이동 로더는4열×4행을 분할하고 기본 행 순서는 down/up/left/right이며, 이동은4프레임 순환·정지는0번/위상0이다. 좌우2행 시트를 이 경로에 그대로 넣거나 앞뒤 그림을 임의로 만들어 채우지 않는다. 요청한 방향과 지원 방향을 명시해 별도 대응이 필요한지 확인한다. 좌우만 요청했다면 앞뒤는 제외/미제작으로 기록하고, 요청한 방향이 빠진 경우에만 미완료로 전달한다.

별도 동작은 [character-motions.js](../../../src/data/character-motions.js)의 프레임별 rect/pivot/duration과 [character-motion.js](../../../src/world/character-motion.js)의 재생 소유를 따른다. 반복은 엔티티, 일회성은 컷신 waiter가 갱신한다. 새 연결마다 이동→정지→방향 변경, idle→행동→같은 외형 상태 복귀, 행동 중 다른 동작으로 교체/중단, one-shot 완료를 실제 장면에서 확인한다. 이전 waiter가 새 동작을 지우거나 완료 사건을 두 번 적용하지 않아야 한다.

[playbackFrameAt](../../../src/ui/battle-preview.js)의 시간 기반 선택과 실제 호출부를 대조해 짧은/긴 dt, 프레임 경계, loop의 마지막→첫 프레임, one-shot 마지막 프레임/종료에서 범위 밖 인덱스·빈 화면·피벗 튐이 없는지 본다. 순환을 위해 모든 동작을 강제로 반복시키거나 완료 때 다른 몸체/의상 단계로 초기화하지 않는다. 이 런타임 검증과 제작자의 포즈/GIF 검수는 각각 결과를 남긴다.

파일 확인 → 등록/프레임 확인 → 실제 장면의 시작/중간/종료 확인을 구분해 보고한다. 제작 요청만 받은 작업은 자산 전달로 끝내고, 게임 연결을 요청받았으면 runtime에서 해당 캐릭터가 올바른 모습으로 보일 때까지 확인한다. 스프라이트를 기다리는 임시 표현은 완성으로 보고하거나 사용자 플레이 버전에 그대로 내보내지 않는다.
