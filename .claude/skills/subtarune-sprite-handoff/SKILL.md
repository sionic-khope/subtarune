# 스프라이트 제작과 코딩의 전달 계약

사용자 선호(2026-09-14): 생성 스프라이트는 Codex 제작 담당에게 맡기고 Claude 등 다른 모델은 코딩을 할 수 있다. 어느 모델이 코딩하든 아래 계약을 공유한다. 사용자의 후속 담당 변경이 우선한다.

## 코드 작성자가 먼저 할 일

1. 기존 `assets/source/`, `assets/sprites/`, `assets/enemies/`, `docs/handoffs/`에서 승인 자산과 사용처를 찾는다. 이미 만든 관중/인사 시트가 안 보이면 경로·preload·레지스트리·프레임·hidden·레이어·카메라를 먼저 조사한다. 파일을 다시 생성하는 것은 연결 실패의 해결책이 아니다.
2. 새 그림이 필요하면 제작 요청에 캐릭터/참조 원본, 쓰일 화면과 동작, 방향, 셀 크기·행열·프레임 순서/시간, 투명 배경, 발/무기 피벗, 목표 화면 크기, 보존할 외형, 출력 경로를 적는다. 기존 자산의 규격이 우선이며 보스를 모두64px로 정규화하지 않는다.
3. 사용 가능한 이미지 제작 담당에게 `pixel-character-sprites`/`generate2dsprite`/`imagegen`의 해당 절차로 전달한다. 담당/도구가 없으면 기존 자산으로 가능한 코드 작업을 진행하고, 없는 그림과 미확인 사항을 전달한다. 생성 능력이 있다고 가장하거나 코드로 캐릭터 도트를 임의 재디자인하지 않는다.

## 제작 결과에 필요한 것

최종 PNG/시트, 원본과 실제 프롬프트, 프레임 순서·duration·pivot·공통 scale, 투명도/색키·최근접 처리, 방향별 또는 동작 미리보기, 알려진 한계를 해당 `assets/source/<작업>/` 계약에 둔다. 기존 원본과 반려 초안을 최종 자산과 구별한다. 재현 스크립트는 실제 입력 경로와 결과를 갖는다.

## 통합자가 검증할 것

등록 흐름은 `src/data/characters.js`, `character-motions.js`, `src/world/character-motion.js`, 해당 맵 preload, 전투 enemy/sheet/pivot 사용처를 따라간다. 기존 클래스 이름만 보고 사람형 폴백을 허용하지 않는다.

프레임을 바꿀 때 발 고정, 몸통·머리 비율, 손/무기의 접점, 방향별 정체성, 시트 경계, 알파 가장자리, 근접/전체 구도에서의 화면 크기를 확인한다. 시트 자체의 움직임 위에 임의 sway/회전/늘이기를 겹치지 않는다. 그림 rect와 충돌/조사 rect는 역할별로 분리한다.

파일 확인 → 등록/프레임 확인 → 실제 장면의 시작/중간/종료 확인을 구분해 보고한다. 제작 요청만 받은 작업은 자산 전달로 끝내고, 게임 연결을 요청받았으면 runtime에서 해당 캐릭터가 올바른 모습으로 보일 때까지 확인한다. 스프라이트를 기다리는 임시 표현은 완성으로 보고하거나 사용자 플레이 버전에 그대로 내보내지 않는다.
