# 모델을 교체할 수 있는 스프라이트 제작

모델은 그림을 만드는 수단이고 승인된 자산이 외형 기준이다. Fable/Claude/Codex가 같은 파일을 읽는다. 모델 교체가 얼굴·비율·스타일을 다시 정하는 허가는 아니다.

## 작업 순서

1. **기준 고정:** [승인 자산 찾기](references/accepted-assets.md)에서 해당 캐릭터의 현재 runtime PNG·원본·계약을 찾고 실제 그림을 연다. 최신 사용자 교정, 바꿀 동작, 보존할 특징, 일반 설정/이번 상태 변형을 요청서에 구분한다. 이미 있는 그림이 안 보이는 문제는 handoff의 등록 검사를 먼저 한다.
2. **생성 계약:** [제작 계약](../../../docs/development/sprite-production.md)의 요청 항목을 채운다. 원본과 스타일 예시, 발/몸체 크기 기준의 역할을 나눠 첨부한다. 프롬프트는 현재 요청과 기준 그림에서 작성한다. 과거 프롬프트의 반려 특징을 새 기본값으로 가져오지 않는다.
3. **모델 연결:** [공급자 선택](references/providers.md)에서 실제 도구·정확한 모델 ID·참고 이미지 전송·비용 경계를 확인한다. Codex 내장 도구를 선택했을 때만 그 환경의 imagegen/generate2dsprite 실행법을 사용한다. 다른 API에서는 이 공통 계약을 유지하며 그 API의 검증된 입력 형식으로 바꾼다. 이 스킬 자체는 API 호출기나 설치된 이미지 모델이 아니다.
4. **작게 생성:** 기존 자산 교체 전에 요청의 한 동작을 별도 후보 경로에 만든다. 시트가 불안정하면 캐릭터 기준을 다시 고정하고 해당 동작/방향만 재생성한다. 프레임별 체형 보정이나 runtime 늘이기로 다른 인물을 숨기지 않는다.
5. **후처리와 채택:** 제작 계약의 최종 PNG 검사와 동작 비교를 수행한다. 후처리 도구가 이 컴퓨터에 없으면 경로를 꾸며 실행했다고 쓰지 말고, 기존 저장소 처리기를 확인하거나 재현 가능한 처리 단계를 인계한다. 사용할 수 있는 처리기가 없으면 raw 후보와 남은 처리를 명시하고 ready로 올리지 않는다.
6. **전달:** 원본·실제 프롬프트·모델/설정·참조·최종 PNG·프레임/시간/피벗·검수 결과를 함께 넘긴다. 이미지 납품은 자산 검수까지, 게임 연결 요청은 [sprite-handoff](../subtarune-sprite-handoff/SKILL.md)의 실제 등록/장면 재생까지다.

## 모델 교체 통과 기준

같은 승인 레퍼런스와 같은 요청으로 후보를 비교한다. 얼굴/의상 정체성, 도트 크기, 정확한 프레임/방향, 행동 판독, 몸체 크기/발 기준, 투명도, 최종 게임 크기에서 하나라도 실패하면 가격이 싸도 채택하지 않는다. 이동·전투·소품을 모두 만들 공급자라면 세 범주에서 각각 비교하되, 단일 소품 요청에 전체 벤치마크를 강제하지 않는다.

가격은 **전체 시도 비용 ÷ 채택된 납품물 수**로 기록한다. 이미지 한 장, 한 동작 시트, 이동+공격 묶음을 구별한다. 동일 결과/동일 seed/동일 품질을 다른 모델에서 보장하지 않으며, 재시도 횟수·비용 상한에 도달하면 현재 결과와 미달 기준을 반환한다.
