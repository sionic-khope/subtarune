# 섭타룬 메뉴와 게임 UI

[공통 판단 기준](../../../docs/development/quality-contract.md), [전투 UI 회고](../../../docs/postmortems/2026-09-10-battle-ui-feedback.md), [레이아웃 회고](../../../docs/postmortems/2026-09-11-layout-issues.md)를 읽는다. 웹사이트 카드 UI 관습보다 현재 게임의 실제 화면과 사용자 참고 구성을 기준으로 한다.

1. 현재 메뉴를 실제 입력으로 열어 화면과 상태 전이를 기록한다. V 메뉴, C 확인, X 취소와 해당 게임패드 대응은 `src/core/input.js`와 호출부에서 확인한다. 키 설명과 실제 입력이 일치해야 한다. 연타 버그는 하나의 입력이 중복 소비된 것인지, 의도적인 다음 선택인지 재현해서 구별한다. 원인을 확인하기 전에 임의 시간 잠금을 정답으로 정하지 않는다.
2. 화면 예산을 `src/core/layout.js`에서 읽는다. 현재 480×360 내부 화면의 UI와 CSS 표시 크기를 구분한다. 그림 크기뿐 아니라 한글 줄바꿈·초상화 여백·선택 커서·패널 경계의 사각형을 계산한다.
3. 전투 UI는 행동 선택 중 잡담 문구, 버튼 줄, 별도 하단 HP 띠가 기준이다. 새 행동도 현재 상태 흐름 안에서 배치한다. 항목을 추가하며 잡담을 별도 턴으로 밀거나 HP 띠를 카드로 재구성하지 않는다.
4. 목록은 0개/1개/표시 창 초과/마지막 항목, 선택지는 실제 행·열 이동과 취소, 입력은 한 번/길게 누름/연타를 확인한다. 커서가 창 밖으로 나가지 않고 현재 선택이 읽혀야 한다. 항목 수가 늘면 스크롤 창과 위치 표시로 대응한다.
5. 행동 가능/불가능/완료가 구별되게 한다. 기존 confirm/cancel/menu/open/close 피드백을 재사용하고, 구매 불가·대상 없음·회복 불가·아이템 소진에서 이유와 결과를 확인한다. 취소는 돈/아이템/전투 행동을 소비하지 않아야 한다.
6. 수정한 상태부터 원래 조작으로 돌아갈 때까지 실행한다. 전투는 목표 취소, 이전 동료 계획 취소, 쓰러진 멤버 제외, 전원 패배/재도전 중 해당 변경이 닿는 경로를 포함한다. 보상은 실제 돈/HP/아이템과 획득음·문구가 일치해야 한다.

## 확인 도구와 범위

`tests/unit/menu-layout.test.mjs`, `dialogue_parser.test.mjs`, `layout.test.mjs`, `items.test.mjs`, `shop.test.mjs`와 `tests/playtest/battle.mjs`가 기존 계약 사례다. 긴 한글/최대 목록/초상화 포함 화면을 375·768·1280px에서 확인하되, 테스트를 위해 기존 대사를 영구 교체하지 않는다. 실제 입력과 한글 가림·테두리 겹침·비활성 표시를 눈으로 본다. 파일만 존재하거나 커서 인덱스만 맞는 것으로 UI 완료를 판정하지 않는다.
