# BUILD310 · 말자하섭 보라 토리이 추격

## Overview

기억의 방2→갈림목 협력 연출→요플래 단독 토리이 달리기→말자하섭 반격전→오른쪽 도착과 북쪽 닫힌 문까지다. 최신 사용자 확정은 다섯 번 반격 승리, 약1~2분, 기존 X 점프/C 베기 유지다. 승리 문구 없이 달리기 제동과 페이드로 다음 맵에 연결한다. 이후 문 너머 사건은 범위 밖이다.

## Player Fantasy

동료들이 뒤에서 적을 막는 동안 결계를 달려 뚫는다. 큰 구체는 뛰어넘고 작은 공허충은 베며, 말자하섭이 직접 접근한 순간 강한 반격으로 체력을 깎는다. 검은 오라는 위협을 키우되 보스 얼굴과 대응할 공간은 가리지 않는다.

## Detailed Rules

- 갈림목 대사/카메라/마리오의 무언 점프 후 빠맨의 “몸조심하세요 형.”에서 단독 진행으로 이어진다. 재입장 시 방어 중인 동료 배치와 단독 파티를 복원한다.
- 기존 준비·출발 이후 실제 달리기3초에 전투를 시작한다. 현재 runner 상태와 화면 위치를 넘겨 점프/베기 자세가 갑자기 초기화되지 않게 한다. 음악은 기존 `castle_battle`을 사용한다.
- 말자하섭은 왼쪽 하늘→우상단5초 진입 후 Q/W/돌진을 순환한다. Q의 낮은 두 구체는 점프, W의 세 공허충은 베기로 대응한다. Q 예고에는 피해가 없고 W 세 마리에 소환음을 세 번 중첩하지 않는다.
- 돌진은 예고 후 출발 시점 목표로 날아오며 추적하지 않는다. 유효한 C 베기가 닿으면 `malzahar_counter` 피해1을 공통 `hitEnemy`로 적용한다. 보스마다 다섯 번만 별도 숫자로 세는 HUD 대신 실제 잔여HP와 감소 막대를 표시한다.
- 다섯 번째 명중 후 위협 제거→공중 공격/착지 마무리→제동→정지 화면 페이드아웃→`gajaeman_torii_end` 도착→`castle_right` 명시 복귀→페이드인이다. 도착한 요플래는 혼자이고 북쪽 문 C는 잠긴 문 반응이다.
- 배경에는 빠맨 대 워윅섭, 비데 대 이즈리얼섭, 마리오 대 야스오섭, 경섭 대 아칼리섭이 작게 싸운다. 이 싸움은 장식이며 전경 충돌/HP에 관여하지 않는다.

## Formulas

- 체력: `HP = max(0, 5 - n)`. `n`은 성공한 돌진 반격 수(0~5), `HP`는 잔여 체력(0~5)이다. 예를 들어 두 번 성공하면HP3/5, 채움 비율60%다. 반격당1, 그 외 보스 피해 차단. 공통 전투 API가 승패와 보상을 소유한다.
- 보스 HP 실체 막대는1피해를0.16초에 줄이고, 피해 잔상 띠는0.3초 기다렸다가 따라간다. 분모는 최대HP이며 명중 누적 수를 잔여HP로 표시하지 않는다.
- 기본 Q는0.85초 준비 후245px/s, 실체 반경17px, 두 발 간격52px다. W는 세 마리,0.95초 간격,220px/s다. 돌진은1.1초 예고·275px/s다.
- 공통 피격은15피해/0.9초 무적. 한 순환15초와 진입5초를 바탕으로 다섯 번 성공 시 약1~2분을 목표로 한다. 실제 플레이 시간·체감 난도는 검증 기록과 구분한다.

## Edge Cases

공중 베기로 마지막 반격에 성공해도 공중에서 멈추지 않는다. 연속 프레임이 같은 돌진에 중복 피해를 넣거나 끝난 뒤 탄이 피해를 넣지 않아야 한다. 패배/재도전은 적HP·횟수·탄·잔상·제동 상태를 새로 구성하고 완료 플래그를 잘못 세우지 않는다. 타이틀/QA/맵 변경은 모드 임시 효과와 원래 runner를 정리한다. 컷신 중 맵 변경은 자동 BGM 재생을 기대하지 않고 후속 노드에서 곡을 명시한다. 완료 저장 후 재입장은 전투를 다시 시작하지 않는다.

이 구조는 미래 달리기 기믹의 재사용 경계이지 모든 보스를 등록만으로 만드는 범용 팩토리가 아니다. 새 요구는 먼저 runner 입력/물리, 모드 수명주기, 구간 데이터 중 소유 위치를 고른다. 이번 공격을 새 기믹에 복사한 뒤 공통 엔진을 다시 만드는 방식은 피한다. 진입→실행→정지→마지막 그림→페이드→도착 음악과 중단/패배 경로를 함께 연결한다.

## Tuning Knobs

수치는 `MALZAHAR_RUNNER`가 원본이다. `q.speed/spacing/warn`은 점프 타이밍, `w.every/speed`는 베기 간격, `dash.warn/speed`는 반격 반응시간을 바꾼다. `player.scale` 변경은 그림과 판정을 함께 확인한다. 오라·잔상·배경 개수로 실제 판정을 늘리지 않는다. 다섯 번 성공과 X/C 입력은 확정 규칙이며 난도 조정 핑계로 바꾸지 않는다. 원경 시간/크기는 `MALZAHAR_BACKGROUND`에만 둔다.

별도 플레이 검증 없이 안전하다고 승인한 조정 범위는 현재값뿐이다(Q245px/s·예고0.85초, W220px/s·간격0.95초, 돌진275px/s·예고1.1초, 몸 배율0.9). 값을 늘리거나 줄이는 실험은 회피·반격·그림/판정 회귀를 다시 통과해야 한다. 예고 시간을0으로 만들거나 실제 이동속도보다 빠른 대응을 요구하는 조합은 허용 범위가 아니다.

## Acceptance Criteria

1. 기억의 방2에서 실제 북쪽 출구로 진입하여 지정 대사, 세 카메라 구도, 파티 분리와 재입장을 확인한다.
2. 필드 X/C→3초 달리기→전투에서 같은 점프/베기를 사용하고 Q 점프, W 세 번 베기, 돌진 예고/반격을 관찰한다. 수치 검사만으로 반응하기 쉬운 난도라고 결론내지 않는다.
3. 반격마다5→4→3→2→1→0 체력과 잔상 띠, 타격음/섬광/흔들림을 확인한다. 마지막 공중 반격도 착지·제동 후 페이드하며 일반 승리 문구/기본 전투 배치가 노출되지 않아야 한다.
4. 오른쪽 끝 맵의 안전한 발판, 북쪽 문 C, 실제 증가하는 필드 BGM 시계, 혼자 이동/메뉴/저장/재입장을 확인한다.
5. 패배/재도전·Esc 중단과 기존 토리이 회귀를 검사한다. 단위 경계는 `malzahar-runner.test.mjs`, `battle-victory.test.mjs`, `castle-malzahar-maps.test.mjs`; 실제 경로는 `castle-malzahar-scene.mjs`, `castle-malzahar-battle.mjs`가 담당한다. PASS 여부와 실행 증거는 `docs/STATE.md`에서 관리한다.
