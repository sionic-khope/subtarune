# 선장실 정체 공개

2026-09-13 사용자 브리핑. 정사 수준: Established(대사/세계 공개), Provisional(사라진 가재맨의 짧은 재실체화 동선 해석). 실제 대사 원본은 `src/data/cutscenes/captain_reveal.js`이며 신규 전투는 만들지 않는다.

## 흐름

1. `maillard_captain` 첫 진입: 기존 문 선택→철컥/검정 전환이 끝난 다음 실행한다. Q 선장실 진입도 같은 흐름이다.
2. 브금 정지→조타대 쥰희(오른쪽)로 팬→“왔군”→중앙 이동→빠맨/요플래/경섭 아래64px 간격으로 등장.
3. 원문 세계 설명→요플래 제외 둘의 느낌표→컴퓨터 공개 순간 천둥/노란 강조→점프/느낌표.
4. 쥰희 가리키기 포즈→둘이 좌우에서 요플래 응시→정체 추궁. 요플래는 고개를 숙여 끄덕인다.
5. `captain_reveal` 곡과 검은 구름이3.4초 확산. 나레이션 뒤 연기가 왼쪽 위로3초 응축하며 **원래 요플래는 그대로** 남고 별도 가재맨이 나타난다.
6. 지정 대화→가재맨을3초 감싸서 숨김→검은 연기가3초 쥰희에게 이동→쥰희 뒷걸음/떨림.
7. 가재맨이 연기에서 오른쪽에 잠깐 다시 실체화해 달아난다. 이는 “사라짐 뒤 오른쪽 도주를 막는다”는 두 지시를 연결하는 시각 비트이며 새 대사는 없다. 요플래가 질주로 막다가 아래로 날아가 누움→둘이 달려와 일으킨다.
8. 쥰희 팬→브금 정지/변신음/흰 전환→이타치 검은 머리·붉은 눈·아카츠키 옷의 **만카츠키 쥰희**→`captain_mankatsuki` 곡→전원 복귀/최종 원문 대사→대치 상태 조작 복귀.

## 상태 계약

- `captain_reveal_started`: map.enter 1회 가드. 중간 저장은 기존 엔진이 차단하므로 중단 후에는 직전 진입 저장에서 재시작한다.
- `captain_reveal_done`: 최종 대사 완료 후에만 설정. 재방문은 일반 쥰희와 임시 가재맨 없이 `captain_mankatsuki` NPC를 복원한다.
- 새 아이템·재화·공격력·HP·전투 시작 없음. 기존 Q 선장실 한 항목과 기존 파티 상태 유도를 사용한다.
- 문 컷신 내부 map 노드는 도착 이벤트를 바로 실행할 수 없으므로 그 runner가 끝난 뒤 `runMapEnter()`를 호출한다. 기존 완료 콜백/저장을 보존한다.

## 집중 실제 재생 확인

1. Q 선장실로 가는 길→상단 오른쪽 문 C→경고/네→쥰희 첫 대사와 무음. 실제 입장 버튼 흐름과 Q 선장실 직접 진입 둘 다 확인한다.
2. 팬/중앙 배치, 최초 두 느낌표에 요플래 제외, 천둥 비트, 가리키기, 왼쪽 위 가재맨 응축 중간 화면,3초 감싸기/전이, 질주/낙하/도움/변신 화면을 확인한다. 대화창 위 인물 간격/가림/가구 통과를 본다.
3. 마지막 대사 후 원본 요플래/동료 둘/만카츠키 쥰희 존재, 연기/임시 가재맨 없음, 조작 가능/전투 없음, 지정 두 번째 곡 유지.
4. 실제 저장 후 이어하기/방 왕복에서 변신과 완료 플래그가 유지되고 대사가 반복되지 않는지 확인한다. 중간 연기에서 Esc 시 타이틀과 다음 게임에 검은 효과가 남지 않는지 확인한다.

집중 유닛: `node --test tests/unit/captain-reveal.test.mjs tests/unit/captain-room.test.mjs tests/unit/cutscenes.test.mjs`. 전체 게임 재플레이는 이 요청 범위가 아니다.
