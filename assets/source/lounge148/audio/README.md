# 영클전함 라운지 네 목소리

비데와 파크가디언 두 모습은 `tools/audio/lounge148_voices.mjs`의 수학적 비언어 모음 합성이다. 럭키가이는 사용자가 첫 합성안을 전자음처럼 느낀다는 피드백에 따라 macOS 기본 한국어 Eddy TTS의 ‘헤’ 한 음절로 교체했다. 외부 음원이나 실존 인물 녹음·목소리 복제는 사용하지 않는다. 비데의 아스고어 언급은 낮고 둥근 목소리 방향을 위한 참고이며 게임 원본 샘플을 복제한 결과가 아니다.

`node tools/audio/lounge148_voices.mjs`로 4종 MP3·인코딩 전 WAV·반복 미리듣기 WAV·측정 manifest를 재생성한다. Node와 ffmpeg/libmp3lame이 필요하다. 기본파와 최대20배음·두 공명 대역으로 만든3종과 럭키가이 TTS 모두44.1kHz 모노,5ms 어택·25ms 릴리스, libmp3lame quality2다. 모든 계수·TTS 가공 필터는 생성기와 `manifest.json`에 기록한다.

럭키가이 원본은 `say -v 'Eddy (한국어(한국))' -r 190 -o lucky_guy-eddy-he.aiff '헤'`로 생성했다. 저장된 AIFF가 있으면 재사용하며 없으면 macOS에서 생성한다. 원본은22050Hz 모노, 발음 뒤 침묵을 포함한0.782676초다. 1.08배 음높이/속도로 살짝 올리고 앞0.19초를 사용한다. 필터는 `asetrate=23814,aresample=44100,atrim=duration=0.19,acompressor=threshold=0.02:ratio=4:attack=0.3:release=40,afade=t=in:d=0.005,afade=t=out:st=0.165:d=0.025`. 마지막으로 표본 양 끝을0으로 두고 peak0.28로 맞춘다. 출처 AIFF의 SHA256도 manifest에 기록한다.

| 캐릭터 | 기본 음높이 | 길이 | 방향 |
|---|---|---|---|
| 비데 / warm_bidet | 88→80Hz | 170ms | 낮은 공명과 기본파를 강화한 굵고 둥근 비음 |
| 럭키가이 / lucky_guy | 한국어 Eddy TTS ×1.08 | 190ms | 짧고 장난스러운 ‘헤’ 발음 |
| 파크가디언 인형탈 / park_guardian_costume | 410→450Hz | 160ms | 부드럽고 밝게 올라가는 공주 음색 |
| 파크가디언 본체 / park_guardian | 104→96Hz | 175ms | 인형탈 모습과 대비되는 매우 굵은 음색 |

사용자가 비데를 직접 듣고 더 굵게 요청해 기본 음높이를122→112Hz에서88→80Hz로 낮추고 공명도380/900Hz에서270/650Hz로 내렸다. 기본파 비중은0.70→0.85로 높였으며, 목표 peak는0.30→0.27로 낮춰 음량 증가를 피했다. 실제 RMS는−20.00→−19.79dBFS다. 파크가디언 두 음성의 원본 WAV와 MP3는 이전 버전과 바이트가 같다.

`*-source.wav`는 MP3 인코딩 전 PCM, `*-preview.wav`는 디코드된 MP3를0.85배로8회 반복한 청취용 결과다. `all-voices-preview.wav`는 위 표 순서로 재생한다. 미리듣기는 파일 소리 비교용이며 실제 대사 속도는 글자 진행 시각의 영향을 받는다. 런타임은 rate1·cut:false로 전체 샘플을 재생하고 샘플보다20ms 긴 최소 간격을 둔다. 기존 엔진의8ms 모노 교차 페이드는 유지한다.

`manifest.json`의 길이는 MP3 전체 디코드 샘플 수 기준으로 계산한다. 컨테이너 길이는 MP3 패딩 때문에 길게 표시될 수 있다. 피크·RMS·SHA-256도 실제 MP3에 대한 측정이다. 자동 검사는 파형과 브라우저 재생을 확인하며 주관적 음색 청취를 대신하지 않는다.
