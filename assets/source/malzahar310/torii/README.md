# BUILD310 보라 토리이 팔레트 변형

요청은 기존 파란 토리이의 색만 보라색으로 바꾸고 동작을 유지하는 것이다. 내장 image_gen의 참조 편집 결과 `purple-palette-reference.png`는 새 보라 팔레트의 공급원이며 런타임 형상으로 쓰지 않는다. 생성 결과의 기하가 기존 문과 조금 달라 기존 두 레이어에 팔레트만 기계적으로 대응시켰다. 모델/품질 옵션/비용은 도구가 노출하지 않아 특정 버전으로 단정하지 않는다.

생성 도구 출력은 `/Users/khope@sionic.ai/.codex/generated_images/01a09daa-6644-71a0-a0b4-284c735f3b96/exec-967f7324-2dec-41c6-9de6-6bfe82450b67.png`에서 보존 파일로 옮겼다. 실제 호출 프롬프트 전문은 현재 기록에 남아 있지 않아 감사할 수 없다. 위 요청 요약을 정확한 호출문으로 가장하지 않는다. 따라서 보존된 팔레트에서 런타임 PNG를 재현하는 과정은 재실행 가능하지만 이미지 생성 자체를 동일 프롬프트로 재실행할 수 있다는 주장은 하지 않는다.

## 입력과 출력

| 기존 입력 | 최종 출력 | 보존 규격 |
| --- | --- | --- |
| `assets/props/jjajang_torii_blue_back.png` | `assets/props/jjajang_torii_purple_back.png` | 40×95 |
| `assets/props/jjajang_torii_blue_front.png` | `assets/props/jjajang_torii_purple_front.png` | 246×285 |

두 PNG는 원래 색키와 레이어 구조를 유지한다. 팔레트 참조를 전체 이미지에 덮어붙이거나 생성한 문을 억지로 늘이지 않는다. 원본 지붕·검은 밑동·붉은 내부·마젠타 색키·모든 좌표·알파는 변경하지 않는다.

## 재현

`export.cjs`는 `sharp`가 제공되는 환경에서 저장소 루트 기준 다음과 같이 실행한다.

```sh
node assets/source/malzahar310/torii/export.cjs
```

별도 설치된 sharp를 쓰면 `SPRITE_SHARP`에 그 모듈 경로를 지정한다. 생성 이미지에서 보라 픽셀의 밝기별 색을 채집하고, 기존 이미지의 파랑 조건 `b >= 55`, `b > r × 1.4`, `b > g × 1.05`를 만족하는 픽셀만 가장 가까운 파랑 밝기의 보라색으로 교체한다. 리사이즈·안티앨리어싱·윤곽 재작성·알파 변경은 하지 않는다. 현재 출력 로그의 변경 픽셀은 back1466/front10899다.

새 색 생성과 기존 형상 보존 처리는 구분한다. PNG 생성/차원 확인만으로 게임의 앞뒤 가림·통과·달리기 동작까지 검증된 것은 아니다. 해당 검수는 BUILD310 실제 토리이 경로에서 별도로 수행한다.
