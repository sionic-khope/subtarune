# 기존 몸체 보존·깃발만 수정 v4

최신 사용자는 첨부한 기존 v2의 몸·표정·색·포즈를 그대로 유지하고 깃발만 바꾸도록 지정했다. 이 결과는 이미지 생성 도구의 깃발 수정 후보를 기계적으로 추출한 것이며 사용자 최종 승인을 뜻하지 않는다. 회색 머리·새 몸체의 v3는 이 요청의 기준이 아니다.

`raw/user-target.png`는 사용자 첨부, `raw/flag-edit.png`는 내장 이미지 생성 결과, `raw/accepted-runtime.png`는 몸체 보존 기준인 기존 v2 runtime이다. `prompt.txt`는 실제 생성 지시다. 정확한 백엔드 모델 ID·비용은 도구에서 제공되지 않았다.

후처리는 각192px셀의 x0~69 깃발 영역만 새 생성 픽셀로 교체했다. 생성본 알파240미만을 제거하고 기존 v2 프레임별 샘플링·배치와 같은 최근접 좌표를 사용한다. x70~191의 얼굴·몸통·손·망토·짧은 다리 영역은 RGBA 바이트 단위로 원본과 동일하다. 새 그림이나 픽셀 재도색은 없다. 보이는 변경 픽셀은 프레임별1909/2109/2007/1936, 깃발 영역 밖 변경0이다.

최종 `janitor-hero-idle.png`:384×384,192셀2×2,공통피벗[138,180],시간380/260/380/260ms. 기존 몸 크기·포즈·바닥 정렬은 유지된다. 가시영역은 각각[3,102,173,181]/[4,102,172,184]/[3,103,173,182]/[3,102,172,181]로 경계 접촉이 없다. 비교 이미지의 윗줄은 기존, 아랫줄은 깃발 수정 후보다. 독립 검수 후 runtime PNG에 복사했다. 초기 metadata의 runtime_integrated:false는 첫 후보 추출 시점 기록이다.

재현: `uv run assets/source/janitor-hero-v4-flag-only/export.py`.

공격 참고 가이드는 두 번째 중립 프레임 가시영역을 make_anchor_layout.py로2열3행512셀에 반복한 뒤 각 셀 전체를 왼쪽60px 이동한 배치다. 이 이동은 무기 뒤쪽 여백과 전방 공격 여백을 확보하며 그림을 바꾸지 않는다. 설정은 subject-height-ratio0.32,width-ratio0.72,feet-ratio0.80. 가이드의 몸 키약156px, runtime256셀에서는약78px가 목표다. 생성용 가이드의 스크립트 기본 LANCZOS와 runtime PNG의 NEAREST 처리는 별개다. 이 가이드는 신규 포즈를 생성한 공격 시트가 아니다.

## 최종 통합 자산

- 대기·서기·웃음은 `assets/battle/janitor-hero-{idle,stand,laugh}.png`, 192셀,피벗[138,180]이다. `export-poses.py`는 기존 v2 서기/웃음 몸체를 그대로 두고 생성된 천 깃발 영역만 교체한다. 웃음 편집 원본은 윗깃대가 분리되어 채택하지 않았고, 연결이 완전한 서기 편집 원본의 깃발을 왼쪽5px 이동해 기존 웃음 손의 깃대에 맞췄다. 마스크 밖 변경0이며 새 픽셀을 그리지 않았다.
- 단독 천 깃발은 `assets/props/janitor-hero-flag.png`, 192셀,피벗[96,96]이다. `flag-raw.png`를0.12배 최근접 축소했으며 금속 칼날이 없다.
- 공격은 `assets/battle/janitor-hero-attack.png`,320셀2열3행(640×960),피벗[164,236],시간220/340/120/100/220/240ms다. `attack/export.py`는 공통0.5배율로 몸 키약78px를 유지한다. 뒤로 젖히는 프레임의 왼쪽150px·후속 프레임의 오른쪽134px까지 담으려면 초기256/288 계획보다 큰320셀이 필요했다. 프레임별 독립 크기 보정은 없다.
- 공격 접촉 프레임3의 오프셋[90,10]은 실제 붉은 천 내부 RGBA(179,1,0,255)다. 바깥 천 끝 근사[115,14]와 구분하며, 게임에서는 드럼통을 천으로 받아친다. x160 몸 기준 배치에서 가장 왼쪽 무기까지10px 여백을 확보한다.
- 삼중 베기는 `assets/fx/janitor-red-triple.png`,128셀2×2,피벗[64,64],16fps다. 채택 원본·처리·검수는 `fx/`로 옮겼다. 각 프레임에 이미 세 겹의 붉은 베기가 포함된다.

최종 자산은 독립 검수 후 runtime에 복사했으며 실제 장면 재생 검증은 통합 담당 범위다. v3 회색 머리 몸체와 첫 경계 침범 공격은 채택하지 않았다.
