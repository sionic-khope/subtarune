# 강퇴창고 악질맨 스프라이트

2026-09-13 사용자 요청: 검은 몸과 굵은 흰색 도트 윤곽, 뒤돌아 웅크린 기본 자세, 양팔을 펼치고 웃는 정면 등장, 여러 춤사위.

모든 원화는 내장 `image_gen`으로 새로 생성했습니다. 기존 캐릭터 그림을 합성하거나 코드로 그린 대체물이 아닙니다. 각 액션의 `raw-sheet.png`가 원본이며 생성 프롬프트는 상위 `*-prompt.txt`에 보존합니다.

## 런타임 계약

| 파일 (`assets/sprites/`) | 셀 | 배열 | 프레임 |
| --- | --- | --- | --- |
| `expelled-viewer.png` | 96×96 | 단일 | 웅크림 0 |
| `expelled-viewer-crouch.png` | 96×96 | 2열×2행 | 뒤돌아 웅크림 4 |
| `expelled-viewer-reveal.png` | 96×96 | 2열×2행 | 팔 내림→양팔 펼침 4 |
| `expelled-viewer-dance.png` | 96×96 | 2열×4행 | 디스코·쪼그림·머리 위 팔·한쪽 무릎·옆 뻗기 등 8 |
| `expelled-viewer-knockdown.png` | 96×96 | 2열×2행 | 낙담→옆으로 쓰러짐 4 |
| `expelled-viewer-down.png` | 96×96 | 단일 | 쓰러짐 마지막 자세 |

모든 프레임 피벗은 `[48,88]`, 순서는 행 우선입니다. 화면 확대는 nearest-neighbor를 사용합니다. 기본 뒷모습에는 얼굴이 없습니다. 정면은 흰색 큰 웃는 입입니다.

## 후처리와 검증

`generate2dsprite.py process`의 크로마키 제거·컴포넌트 추출·QC를 사용했습니다. 액션별 `pipeline-meta.json`에 실제 처리 설정이 있습니다. 기본 처리기의 Lanczos 축소 결과는 런타임에 쓰지 않고, `export-runtime.py`가 정리된 원본에서 nearest-neighbor로 다시 추출합니다. 팔/몸/윤곽을 다시 그리거나 팔레트를 양자화하지 않습니다. 마젠타 혼색 잔여 픽셀만 크로마키 spill 정리합니다.

- reveal/crouch: 같은 1254×1254 원본 격자와 고정 배율 `0.14578352180936993` 공유. 웅크린 몸을 서 있는 키로 억지 확대하지 않습니다.
- dance: 원본 격자는 1024×1536의 직사각 셀입니다. 머리와 신체 해부학적 크기를 맞추는 액션 전체 고정 배율 `0.21`을 적용합니다. 포즈별 확대율 변경은 없습니다.
- 춤 4번(0부터)의 손끝이 소스 셀 경계 y=768에 닿습니다. 바로 위 y=744–767은 전부 투명하며 원화 손끝 윤곽이 완전한 것을 확인했습니다. 소스 경계 접촉만 명시적으로 허용했고 최종 출력 경계 접촉·잘림은 허용하지 않습니다.
- 최종 20프레임은 모두 셀 내부, 불투명 검은 몸 유지, 마젠타 잔여 없음. `runtime-qc.json`에 각 바운딩 박스·배율·불투명 검은 픽셀 수를 기록합니다.
- `contact-preview.png`: 첫 줄 웅크림, 둘째 줄 등장, 셋째·넷째 줄 춤, 다섯째 줄 쓰러짐을 3배 nearest-neighbor로 표시합니다.

재생성: 저장소 루트에서 `uv run assets/source/expelled-viewer/export-runtime.py`.

## 전투 소품과 쓰러짐 추가

후속 사용자 브리핑에 따라 악질맨의 실제 전투(HP 66, 7개 패턴, 보상 666원)와 승리 뒤 쓰러짐으로 범위가 확장되었습니다. 전투 수치·패턴 구현은 런타임 코드가 담당합니다.

`knockdown`도 reveal/crouch와 동일한 원본 배율을 사용합니다. 누운 몸을 다시 서 있는 키로 확대하지 않습니다. 원본에서 발바닥 기준은 누운 포즈에 적합하지 않으므로 추출 QC는 중심 정렬, 최종 시트는 다른 액션과 같은 `[48,88]` 바닥 피벗으로 정렬했습니다.

`assets/battle/expelled-viewer-{chicken,timeout,rock,shard}.png`는 각 32×32 투명 아이콘입니다. 원본 `icons/raw-sheet.png` 자체에 알파가 있습니다. 생성 과정의 희미한 알파 잔여만 128 기준으로 정리하며 RGB 팔레트 양자화는 하지 않습니다. shard는 여러 파편을 하나로 축소하지 않고 원본 오른쪽 아래 묶음의 좌상단 파편 하나만 추출합니다. `export-icons.py`로 재현하고 `icons-qc.json`, `icons-preview.png`로 확인합니다.

## 최초 요청과 후속 범위

최초 요청은 경고문 → NPC 등장·춤 컷신 → 기존 전투 진입 연출까지였고, 후속 요청으로 실제 전투와 승리 연출이 추가되었습니다. 이 에셋 디렉터리는 그림 계약만 정의합니다.
